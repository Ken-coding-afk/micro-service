## 1. 适用范围与总则

1. 文档、业务注释以中文为主；标识符、API、技术术语使用惯用英文。文件 UTF-8，代码换行 LF，格式交给工具固定。
2. 一个服务负责自己的数据与用例。跨服务通过明确 API/事件访问，禁止共享业务实体 jar 和跨库直接查询。
3. API DTO、数据库实体和内部模型区分；禁止直接把数据库实体完整暴露给前端或从请求自动绑定权限、tenant_id、owner_user_id。
4. 输入验证在入口完成，业务规则在 service 完成，数据库约束兜底。错误使用稳定 code；禁止捕获所有异常后返回成功或空列表。
5. 所有远程请求显式超时；写入重试必须有幂等合同；不得在数据库事务内等待模型输出或长期远程调用。
6. 新增租户表必须同时提交迁移、tenant_id 索引/约束/RLS、权限落点和跨租户测试。原生 SQL 也遵守，不能认为绕开 ORM 就不受规范约束。
7. 内部端点也要认证。身份来自验证后的 principal，消息头和请求 JSON 不构成可信身份。
8. 凭证只能通过受控配置注入；`.env`、secret、模型权重、数据样本和用户文件不提交 Git。示例配置不得带可用默认生产密码。
9. 日志描述事件和定位信息，不记录完整请求/响应以“方便排错”。敏感数据脱敏后才能用于测试或问题复现。
10. 依赖固定版本，禁止生产 `latest`、SNAPSHOT 或无锁浮动安装；升级必须记录兼容性和许可证影响。
11. 只实现当前需求。公共包中不得加入某个项目的硬编码业务；普通业务不要为了复用一行代码就新建框架抽象。
12. 时间统一 UTC，服务使用可注入时钟；并发写入使用数据库约束、版本条件或锁，不依赖进程内锁解决多实例一致性。

<a id="structure"></a>

## 2. 目录、分层和命名

服务按业务领域命名，例如 document-service、analysis-service、agent-service；基础职责固定使用 foundation、identity-service、api-gateway、python-sdk。禁止为每个领域机械拆 controller/api/biz/data 四个部署服务。只有真实独立发布与运行需求才新增服务。

Java/Python 服务的唯一目录定义见[业务服务内部目录与职责](../design/01-总体架构与工程结构设计.md#service-layout)。本规范约束分层依赖和命名，不维护重复路径清单。

Controller/API 负责协议转换和入口校验；Service 负责用例、授权落点和事务；DAL/Repository 负责持久化；Client 负责外部合同。不同层不得通过“通用 utils”绕开依赖方向。复杂领域可在对应层内再按领域分包，不强制整套 DDD/CQRS。

业务权限定义随服务源码；数据库迁移随拥有表的服务；Nacos 参数在 config；第三方组件运行与初始化在 infra；应用镜像编排和 Nginx 在 deploy。完整树与文件所有权以[总体架构与工程结构设计](../design/01-总体架构与工程结构设计.md)为准。

<a id="java"></a>

## 3. Java 规范

- 类名 PascalCase、成员 camelCase、包名全小写；业务子包按领域命名。
- 使用构造器注入。单实现 service 默认具体类；需要稳定替换边界或多个实现才建接口，不默认成对 `Service/ServiceImpl`。
- Controller 不写 SQL、不处理跨服务编排；Mapper 不承载业务流程；不要对每个实体建立机械的万能 BaseService。
- 事务放在可被 Spring 拦截的明确用例入口；自调用、异步执行和新线程的事务传播必须显式处理。事务租户上下文与连接一致。
- DAO 与 API 类型独立，复杂转换显式实现或采用经管理的映射工具；不通过反射无差别复制安全字段。
- Gateway 使用响应式客户端和上下文；不能从 Servlet ThreadLocal 取身份，也不能在 event loop 上阻塞调用 JDBC 或同步内省。
- Spotless 统一格式，编译与选定静态规则由 parent 管理；禁止通过全局 suppress 绕过安全或空值问题。

<a id="python"></a>

## 4. Python 与 Agent 规范

- 包/模块/函数 snake_case，类 PascalCase；公共入口、SDK 接口和业务边界必须有类型标注。
- API 用 Pydantic schema 验证；核心 service 尽量接收明确数据类型，避免任意 `dict[str, Any]` 贯穿全流程。
- FastAPI lifespan 管理客户端/模型资源；同进程复用 HTTPX 与数据库连接池，退出时关闭。
- `async` 函数不调用阻塞 IO 或长 CPU/GPU 任务；并发受 semaphore / Worker 配额控制。
- 每个任务独立 DB session 与 tenant ContextVar；错误/取消也必须 reset 上下文，不能把上个请求的租户带入下个请求。
- Ruff 管理格式/lint，mypy 检查公共包与业务边界；模型第三方库缺类型时在边界局部适配，不全项目关闭检查。
- Prompt 与工具定义随版本管理；Agent 工具必须声明输入 schema、权限、超时与副作用；禁止模型任意调用 shell/内网地址。
- 聊天项目使用 SDK 的 Run、事件和检查点入口；禁止把会话权威状态只放进内存、用本地锁替代跨节点控制、在 SDK 之外直接覆盖检查点。恢复/升级必须保留执行版本与工具幂等键。

<a id="contracts"></a>

## 5. API、事件、错误与重试

对外 API 使用稳定版本路径和明确 schema。更新实体用允许字段清单，tenant/owner/权限等安全字段从可信上下文取得；分页有上限，排序字段白名单，文件类型/大小在入口及业务层按合同验证。

HTTP/事件使用一致的标识符、UTC 时间和错误编码，金额/高精度数值不靠浮点跨语言隐式转换。事件包含 event_id、类型/版本、发生时间、租户、trace 和明确 payload；升级必须兼容消费者或发布新版本。详细 JSON 与消息合同引用[Java 与 Python 协作设计](../design/07-Java与Python协作设计.md)，不得在项目中另定义一套冲突格式。

客户端显式连接/读取/整体超时，重试有次数、退避和总预算。幂等键必须与租户、主体、操作和请求摘要绑定，重复不同内容返回冲突。外部请求结果未知时进入可诊断状态，不能捕获异常后返回成功或任意自动补偿。

<a id="security"></a>

## 6. 权限、数据隔离和日志

后端是权限执行点，页面隐藏按钮不能构成授权。权限检查与对象所属租户、状态及数据范围一起执行；机器调用和内部接口也验证。请求 header/JSON tenant_id 不是可信上下文，任何“跨租户管理员模式”都必须是专门、可审计的能力。

每个租户表的迁移必须包含 tenant_id、必要复合唯一约束和索引、RLS 策略；运行账号无 BYPASSRLS/DDL 权限。连接或事务上下文必须在异常/取消后清理。缓存键、对象路径、队列数据、后台任务和日志上下文遵守同一租户边界。

日志输出稳定事件名、错误码和关联 ID；不默认记录聊天全文、用户文件、OAuth code/token 或 secret 内容。排错增加日志也遵守脱敏规则。生产诊断接口不得返回完整环境变量。

<a id="verification"></a>

## 7. 迁移、测试与变更约束

- 已应用的 Flyway / Alembic 迁移不可修改；修复通过新迁移完成。Flyway 与 Alembic 不共同管理同一服务的同一批业务表。
- 任何影响租户、权限、OAuth、任务状态、重试和取消的修改都需要针对性反向测试；只测成功链路不足以验收。
- MQ 消费成功必须以本地事务提交为准；业务事件副作用有去重键。消息 schema 变化须兼容旧消费者或增加版本。
- 测试先明确场景与预期，完成当次实现后集中编写/运行；只运行受影响模块和用例。不自动运行全项目套件，不通过删断言、跳过安全检查让测试通过。
- 假模型用于验证编排，真实模型用于能力质量评估；两者结果分别记录。不能以假模型跑通宣称算法质量合格。
- 文档、注释及行为中性的格式变更不增加无意义单测，但检查链接、示例、命令和合同一致性。

<a id="maintenance"></a>

## 8. 依赖、提交前检查与文档维护

依赖锁、格式工具和静态规则由框架兼容基线固定，业务团队升级时保留版本依据和变更说明。示例必须能在框架源码之外安装构建。生成文件/缓存/密钥不进入源码提交；业务实现不得修改已发布公共包的本地安装目录。

提交前检查与改动相称：代码完成后集中运行受影响测试、适用格式/lint/typecheck/build，记录命令与结果；数据库/权限/跨语言合同变更补充相应验证。未运行或受环境限制的检查明确记录，不以静态检查替代生产验证。

架构、接口、权限、配置、部署或升级行为调整时，先修改相应中文权威设计正文，再更新指南和活跃实施计划的任务/验收；不在文档末尾追加互相覆盖的“补充规定”。普通文字纠错检查链接与章节即可。项目可有更具体领域规则，但不能默默放宽框架的安全与一致性合同。
