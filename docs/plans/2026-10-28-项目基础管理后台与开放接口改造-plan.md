## 1. 目标、范围与验收

交付的是可以完成实际配置的项目基础后台。保留既有平台单入口、认证、租户隔离、角色、密码重置、会话、审计和服务监控基础，在同一 identity-service/admin 中改造，不另建一套后台。

默认使用链路：创建默认租户或选定租户 → 建“公司/研发部/后端组” → 创建有完整常用资料的用户并加入组 → 新建业务权限 → 给角色授权 → 角色分配给用户或组 → Java/Python 业务接口按同一权限码检查 → 查看授权来源、审计和监控。平台账号负责配置，不自动成为业务用户。

| AC | 场景与输入 | 可观察预期 |
| --- | --- | --- |
| AC-01 | 零/单个/多个可用租户；刷新和双标签页 | 零租户可明确创建 default；一个时直达用户页；多个显式选择，URL 独立保存目标；后端不隐式选租户 |
| AC-02 | 创建/编辑用户，含姓名、工号、联系方式、组和直接角色；完整资料表单 | 新资料可查询并持久化；初始关系原子写入；按最终完整资料合同读写；联系邮箱不伪装成已验证邮箱 |
| AC-03 | 创建公司→部门→团队，加入多组，移动组织、搜索及查询下级成员 | 树正确恢复；同租户、无环；成员来源明确；删除非空节点被拒绝 |

| AC-06 | 独立登记的外部 PLATFORM 应用调用 API，不使用后台 Cookie | OAuth+Bearer 可完成租户、用户、组、角色、目录、审计及监控查询；未登记/错主体/错 scope 拒绝；原租户 API 仍可用 |

| AC-08 | 从空库初始化；跨租户、并发移动、过期写入、最后管理员 | 新模型与初始账号/角色/重置流程正确；新表 RLS 生效；并发无环、不丢更新；组不能绕过管理员保护 |
| AC-09 | 新动作成功/失败、凭据操作；监控启用/未启用/故障 | 审计真实主体/目标和脱敏差异，密码不泄漏；监控有真实采样或明确无数据/故障，不展示假正常 |

### 必须整体审阅的决定

1. 用户组就是组织节点，支持多级、多组成员；不再使用平面组方案，不另建重复部门实体。
2. 组上配置角色，用户取得直接组角色；父子层级不自动继承角色。停用父节点使子树组授权失效，但不禁用用户或取消直接角色。
3. 权限定义是项目级，各租户独立给角色分配；后台可新建业务权限，系统/发布权限有来源保护，业务代码仍需声明检查。
4. 单租户体验通过明确创建默认租户及唯一租户直达实现，不再引入一套“无租户”认证模型。
5. 外部管理应用可登记 PLATFORM 身份客户端并使用同一 API，仍受平台用户权限及 scope 限制；不把固定客户端限制简单删除后放任所有身份调用。

执行者可自行决定组件拆分、索引命名及局部 DTO 排布；不得自行改变上述授权/删除/迁移语义。本方案已确认，按最终合同实施。

## 4. 影响范围与迁移

- identity-service：修改最终资料/组表/目录来源定义；开户、资料、组织用例、授权查询、目录维护、控制器、安全策略映射、审计；内置权限和固定客户端维护升级。
- api-gateway：显式新增 BFF 路由、独立 Bearer 监控只读入口；保留租户后台404和现有业务 API。认证上下文不替换成目标租户。
- admin：租户工作区、用户/组织/角色/权限页、导航与统一表格/表单；复用既有 Vue 工具链。
- Java/Python：使用现有权限检查和业务 SELF/TENANT 条件，不新增另一套鉴权 SDK；更新接入示例与真实跨语言验收；仅必要时修正受影响 SDK。
- 直接修改 V1 建库定义加入资料、组织表、组织版本和权限来源；删除本轮 V12/V13 增量文件，不写 UPDATE 回填、双版本读取或最终资料合同层。
- 接口和页面统一为最终合同。租户业务 API 是明确保留的产品能力，不是旧后台兼容入口；已退役页面/过渡适配按实际依赖清理。
- 新建本项目隔离验证库，从零初始化并登记管理员及业务测试账号。28080候选切换到验证通过的新库；原26080和其他项目资源不动，不自动清理其数据。
- 失败时停止候选切换并修正后重建新验证库，不修补旧库Flyway校验和或构造旧数据转换器。
