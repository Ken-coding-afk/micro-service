## 1. 目标、范围与验收

管理台定位为面向项目研发、测试和技术管理员的“身份与访问管理台”。客户业务后台由具体项目按业务需求实现，复用框架身份、角色、权限和认证 API。面向研发不意味着可以依赖手填数据库 ID 或接口拼接完成日常操作。

本次只解决三件事：平台管理员一次登录后管理指定租户；用户、角色、授权、应用接入形成连贯流程；真实验证授权与撤销结果。不能以菜单可见、接口返回 200 或 CI 通过代替产品验收。

### 1.1 功能取舍

| 功能 | 本次处理 | 明确边界 |
| --- | --- | --- |
| 租户管理 | 保留创建、资料、有效期、启停、初始管理员能力；列表增加管理用户/角色入口 | 不做组织树、部门、组织层级或跨项目租户中心 |
| 用户 | 复用查询、创建、编辑、启停、密码重置、角色分配、有效权限和会话关联 | 不增加业务身份字段、邀请/公开注册、批量导入 |
| 角色与权限 | 复用现有角色、授权、成员组件，在同一角色详情中串联；权限目录作为页内只读视图 | 不引入菜单授权、授权委派、权限模拟器或新计算器 |
| 应用与机器身份 | 保留服务 audience 登记、应用登记/编辑/启停、凭据轮换；用现有类型区分用户应用与机器身份 | 允许租户改成搜索选择；协议字段保留，增加必要解释，不改 OAuth 合同 |
| 会话与审计 | 保留现有功能，接入目标租户；审计明确实际平台操作者和目标租户 | 不建设统一日志平台或跨租户业务数据查询 |
| 安全策略、平台管理员 | 保留项目级功能和最后一个有效管理员保护 | 不随租户选择器切换策略，不新增平台角色配置体系 |
| 个人账号、第三方账号绑定、服务监控 | 保留现有入口及原有条件限制 | 不把第三方提供方配置搬到页面，不扩建监控系统 |
| 项目概览、初始化待办、接入帮助中心、权限排查中心 | 本次不新增 | 必要提示直接放在对应页面，操作说明写入现有指南 |

保留现有账号、租户、角色、权限、客户端和历史审计；保留租户管理员入口和 API。未逐项运行的功能不能在交付报告中写成“已完整可用”。

### 3.2 本计划提交确认的具体决定

1. **身份与目标分离。** 平台 token、SecurityContext、`/me` 仍是 platform、tenant_id 为空；URL 中的 tenantId 仅是受控管理目标。禁止伪造租户 principal、从任意 header 建立租户身份或让平台账号自动获得业务资源权限。
2. **新增明确路径。** 平台管理租户身份 API 使用 `/api/v1/identity/platform/tenants/{tenantId}/identity/` 前缀。其下只映射既有用户、角色、目录/有效权限、会话和审计操作；每项 HTTP 方法、尾路径、入参、version、幂等和结果格式沿用对应旧接口。不设置通配转发入口；不暴露 me、OAuth 协议、提供方或业务接口。浏览器使用 `/bff/identity/platform/api/platform/tenants/{tenantId}/identity/`；原租户 API 和 BFF 不变。
3. **固定资格，不建新角色体系。** 新增固定目录权限 `platform:identity:read`、`platform:identity:manage`，对应新 scope `platform.identity`；只供固定平台管理客户端及有效平台管理员使用，不给业务客户端/机器身份/普通角色自动开放。租户身份审计读取仍额外要求既有 `platform:audit:read`。服务端静态映射允许的原 identity 操作，未知操作拒绝。旧 `platform:tenant:manage` 不隐式扩权；目录、固定客户端允许 scope、网关请求 scope 和内省授权映射一起升级，平台旧会话需重新登录授权取得新能力。
4. **共用业务规则。** 新旧入口共用用户/角色/会话用例。现有服务中的鉴权入口、操作者锁定及目标租户来源作最小调整；普通租户路径仍强制 token 租户一致。允许一个身份服务内部的明确管理调用参数承载 actor 类型/ID 和目标租户，禁止创建通用授权策略引擎或传播新的 SDK 全局上下文。
5. **事务与隔离。** 平台入口先验证主体与操作资格；写事务沿用目录锁起始，按“目录 → 平台操作者 → 目标租户 → 既有排序的角色/用户/资源锁”执行并重查状态。平台操作者不参加租户用户锁查询。目标表访问使用同一连接的 LOCAL tenant scope，不改变认证上下文，不跨事务保留；异常回滚。现有租户操作的锁顺序不变，共用对象锁顺序不得反转。
6. **目标失效规则。** 不存在的目标租户/越界对象为 404；停用或到期的租户，其用户、角色、目录、会话和租户身份审计入口统一返回 `403 TENANT_UNAVAILABLE`，页面引导到项目租户管理。租户生命周期、项目审计仍可使用；不新增一套停用租户只读例外。最后一位有效管理员、受保护角色、版本冲突、首次改密和近期认证等现有保护继续生效，近期认证检查真实平台操作者。
7. **审计。** 平台跨租户操作记录 `actor_type=PLATFORM`、真实 actor_id 和目标 tenant_id，复用现有审计字段；成功审计与写入同事务，失败尝试在回滚后独立记录。平台审计显示原平台事件及平台操作者产生的租户事件；租户审计仅显示本租户事件，包含平台对本租户的管理动作。平台读取租户自身身份审计通过选定租户入口，不扩展项目审计为任意跨租户汇总。秘密、凭证和原始异常正文不进入审计。
8. **页面与状态。** 项目级页面无目标租户选择；平台租户内页面使用 `/platform/tenants/:managementTenant/identity/users`、`roles`、`roles/:roleId`、`sessions`、`audits` 路由。路由参数是当前标签页管理目标的唯一来源；刷新可恢复，无全局持久化“当前租户”。未选目标时引导选择，不猜默认租户。租户管理员沿用旧路由，无跨租户选择器。
9. **复用和兼容。** 角色详情包含资料、权限、成员；目录保留为“角色与权限”中的只读视图。原 `/roles`、`/permissions` 链接保留可达并转入相应视图。账户个人页、监控、平台安全和管理员功能不删除。切租户有未保存输入时仅提供取消/放弃切换，选定后重建页面数据；迟到响应不覆盖新目标，不自动重放写请求。
10. **不扩大产品。** 不增加主页大屏、入门流程引擎、专门排查中心、菜单设计器、导入导出、新认证协议、跨项目管理或新运行服务。代码标识/范围说明可以展示，但对象关联使用搜索选择。客户端页面中 service/audience 等真实技术配置保持可编辑，不伪装为可以凭空推断的业务选项。

### 3.3 权限定义与 Java/Python 接入方案

沿用“服务声明操作 → 发布目录 → 租户角色组合权限 → 用户分配角色 → 业务接口验证”的现有路径，不增加直接对账号授权的平行机制。

| 环节 | 谁维护 / 如何处理 | 本轮交付 |
| --- | --- | --- |
| 权限声明 | 研发在所属服务权限清单中定义稳定业务编码、名称、说明、支持范围、oauth_scope；接口执行对应检查 | 在现有开发/SDK指南补一个从声明到调用的短例子，引用真实发布命令；不另建权限编辑器 |
| 目录发布 | 沿用受限发布流程同步；新权限不会自动进入既有角色 | 页面显示服务来源和目录状态；空目录提示尚未发布，不能在页面手造权限 |
| 角色授权 | 管理员按资源选择操作及支持的数据范围 | 权限名称优先，编码辅助可复制；不支持的范围不能选择；未改动无需保存 |
| 用户角色 | 账号可分配多个本租户角色，权限按现有规则合并 | 用户详情展示权限来源；更改角色影响其成员，保存前提示影响，不新建模拟器 |
| Java 接口 | `@RequirePermission(value="业务权限", scope="调用范围")` + `CurrentPrincipal` | 复用 SDK，路由检查身份/权限/范围，业务服务和仓储落实租户、所有者约束 |
| Python 接口 | `require_permission("调用范围", "业务权限")` + FastAPI `Depends`；应用安装 `install_resource_security` | 同一身份服务与目录，保留启动时漏声明检查；业务服务/仓储落实数据范围 |
| OAuth scope | 限定应用/本次 token 的调用范围，可对应多个业务操作 | 日常角色页主要操作 permission；scope 在应用接入和目录技术详情展示，不机械复制一套逐用户 scope 勾选 |

示例名 `java-item` / `python-item` 表示两种示例资源，不要求实际项目按语言拆权限；权限归属按业务资源及所属服务定义。管理台授权不会自动实现部门、共享成员、审批金额或资源状态规则，这些仍由项目业务处理。本轮不增加 ABAC、菜单模型或其他数据范围。

保留实时内省和既有失败关闭策略，不借界面改造加入成功缓存或改令牌格式。Python 当前不缓存成功内省；业务请求会增加身份服务依赖。本次双语言真实验证证明功能和隔离，不宣称容量通过，也不另开压测或性能优化任务。更改角色/账号后检查后续新请求，不承诺终止已通过检查并在执行的业务请求。

### 3.4 界面方向与页面规格

**诊断与方向。** 当前页面的主要问题是重复说明、强弱不分、表单缺少业务分组，导致界面像通用模板。采用清晰、紧凑的桌面管理工具布局：使用者是执行配置的技术管理员，系统负责呈现当前对象、允许动作和真实结果。视觉组织围绕“列表选择对象 → 查看/修改 → 核对变更 → 保存”展开，不靠装饰营造层次。

**框架。** 浅色中性侧栏约 216px；顶栏约 52px，仅放项目名称、已知环境及账号菜单；正文边距 24px，页面标题 22px，仅出现一次。目标租户放在租户内页面标题旁的可搜索选择器，面包屑保留路径。移除通用账号摘要横幅、每个导航项的重复副说明和底部口号；“更换账号/退出”放入账号菜单，敏感动作触发的重新认证入口仍就近显示。项目/环境只显示真实已提供信息，不从截图、主机名推断；未提供不编造。

**视觉实施参数。** 使用系统中文无衬线字体，正文 14px、辅助信息 12px、行高约 1.5；间距采用 4/8/12/16/24px；输入与普通按钮约 34px 高，表格行约 44px；边框浅灰、控件圆角 4～6px，仅对话框保留必要阴影。背景以白/中性浅灰为主，单一蓝色用于选中、链接和主动作；红黄绿只表达危险/警告/结果，且同时有文字。每个表单一个主要提交动作，取消和其他动作使用次要样式；长表单操作区可粘底但不遮挡内容。焦点清晰，普通文字对比度目标至少 4.5:1；可读性优先于密度。

**红线与工作方式。** 不加渐变、玻璃效果、装饰插画、统计卡片、巨大欢迎语、彩色图标墙或进入动画；不引入设计系统包、另一套组件库、远程字体或主题切换。沿用 Vue/现有组件，调整共享 CSS 和本轮页面结构，不把“复用组件”理解为保留旧视觉。先完成租户列表、角色授权、安全策略三个代表页面在实际候选应用中的截图审阅，再将同一规则应用到其余页面；这是 T-04 内的质量检查，不另造一份脱离实现的静态原型或新增审批轮次。

各页面在 1440×900、1280×800 核查；长名称、空列表、多页、表单错误、无权限和保存冲突均需可读。低于桌面宽度允许收起导航和表格区域滚动，不在本轮另做移动端产品。键盘可操作选择器/页签/对话框，关闭对话框后焦点返回触发处，保留原有可访问语义。

## 7. 风险、恢复与交接自检

- **平台能力扩大：** 本次是在固定平台管理员能力中增加租户身份管理。仅新 scope/固定目录组合开放；必须保持平台主体、数据库复查和原租户拒绝测试。不得用放开 BFF 全路径来省事。
- **现有服务依赖认证租户：** 复用不能靠改 token/CallContexts“装成租户用户”。显式目标和现有事务作用域一起调整，检查所有 success/failure 审计和近期认证入口。
- **状态串租户：** 用 URL 目标隔离页面状态；敏感缓存不跨目标共享；多标签与迟到响应单独验收。版本冲突保留本地草稿，但切目标清除，不跨租户带入。
- **升级和回退：** 默认无需业务数据迁移；新增目录与固定客户端 scope 先按现有维护方式安装，再启用新页面。identity 镜像携带管理页，网关配置/请求 scope 需协同更新；新 UI 配旧服务时明确失败，不尝试旧租户路径。回退必须将 identity 镜像、网关配置和固定客户端允许 scope 按变更前快照一起恢复，并撤销本次新 scope 会话；不得删除已经合法产生的租户用户、角色或审计，也不回滚历史 SQL。新增目录是否可留存须通过旧版启动/维护兼容检查后记录，不能假定可直接降级。
- **权限撤销不是写完就验收：** 使用真实普通用户再次访问业务 API，按现有内省缓存/撤销合同记录有效时刻，不引入本计划专属超时放宽。
- **控制范围：** 不更新依赖版本、清理无关脚本、替换 UI 框架或重建既有 QA。确认实施后依项目编码规范读取项目/Java规范；如确需修改 Python 再读 Python 规范。

交接自检：十一项 AC 均有任务和验证；依赖无环；平台主体与目标租户分离；原租户 API 和数据保护明确；新增命名均标注拟新增；当前生效基线与拟修订基线区分；未将浏览器旧环境或历史通过结果计入本计划。实际开工仅核对基线差异，不重新扩大已确认范围。
