## 1. 目标、范围与可观察验收

目标是交付一个普通 Java 或 Python 项目可以直接接入的通用微服务框架。保留已有可用成果，减少身份产品扩展和重复技术实现；不再把潜在业务需求变成框架必交付能力。

最终交付边界保持两个自有基础服务、两个公共包和统一身份管理页面。是否使用某个可选适配由项目需要决定；这里定义的是最终职责，不以“以后全部补回来”的方式延续旧范围。

### 1.1 保留、收窄、移除与替代

| 对象 | 本次处理 | 交付边界 |
| --- | --- | --- |
| identity-service | 保留并精简 | 租户独立账号、认证、OAuth2/OIDC、第三方登录、机器认证、基础 RBAC、客户端与身份审计、固定管理页面 |
| api-gateway | 保留 | 路由、入口鉴权、BFF、限流、代理边界、追踪及通用流式转发；不替业务服务判断对象权限 |
| foundation / python-sdk | 保留并清理业务依赖 | 配置发现、可信身份/租户上下文、HTTP、错误/日志、可选数据库/消息接入；不包装另一套 ORM 或协议引擎 |
| 管理委派与授权上限 | 移除产品能力 | 不保留委派 API/页面/在线决策分支；使用固定平台管理员、租户管理员边界 |
| 独立授权模拟 | 移除 | 保留当前实际权限及角色来源查询；取消模拟输入、模拟 API 与页面 |
| 安全策略 | 收窄 | 项目统一安全策略；取消租户级动态覆盖和委派编辑界面，不删除登录保护、密码保护或撤权能力 |
| 注册 | 收窄当前交付 | 管理员开户、首次改密、账号管理必须可用；公开自注册/邀请及邮件激活另行需求评审，不在本计划实现。保留将来注册的可能性，不以占位 API 冒充支持 |
| OAuth 三方向 | 保留 | 对外 OAuth2/OIDC、第三方登录、机器认证不因精简取消；标准协议交给 Spring 组件 |
| 聊天/Agent/算法任务平台 | 移出框架建设 | 不交付 Run、调度、检查点、工具账本、模型预算、审批、聊天前端或 Agent 多节点验收；不引入 Celery/LangGraph 来继续实现同一业务范围 |
| 消息 | 可选通用能力 | AMQP/JSON、Outbox/Inbox 与去重重试适配；无业务任务表、状态机或回调平台；纯 HTTP 项目无需 RabbitMQ |
| examples | 改为最小接入示例 | 独立 Java/Python 服务、可选消息示例和最小业务 Web；不构建文档分析或聊天产品 |
| 迁移/部署 | 保留并复用组件 | Flyway、Alembic、Compose、Ansible；固定调用与检查，不创建第二套迁移图解析器或运维编排平台 |

不新增菜单权限、管理 npm 包、release-console、通用插件体系、跨项目账号中心、Kubernetes、策略语言或工作流引擎。平台管理员管理租户和接入配置，不获得任意租户业务数据读取权；租户管理员只管理本租户身份与授权，业务访问仍按显式业务角色判断。

### 3.1 身份精简的确定边界

- 管理主体：平台管理员管理平台账号、租户和应用接入；租户管理员管理本租户用户/普通业务角色/授权/会话。两者均不自动拥有业务数据权限。普通业务角色不能包含受保护身份管理能力；历史委派不转成管理员。
- 管理员维护：沿用已有受保护管理员及最后管理员检查；只有有权的管理入口能赋予受保护身份。去掉委派后不得把“有任意业务权限”当成管理资格。普通用户保留本人资料/密码/会话操作。
- 数据授权：角色并集、permission 支持范围、客户端/本次授权 scope/audience 限制继续生效；SELF/TENANT 由业务查询和对象检查落实。前端隐藏不是后端授权。
- 旧入口：委派和模拟接口、前端路由从在线入口移除，旧调用按未知路由返回 404；旧客户端不能借旧 endpoint 执行写入。通用错误结构保持。
- 旧数据：不改 V1—V8 等已应用迁移；保留委派表/审计历史但取消在线读取授权，先不 DROP。实际部署有依赖时停止切换并提供迁移清单；不自动授管理员来维持旧委派操作。
- 策略：平台现有安全默认值作为项目默认；租户覆盖停止编辑。已有覆盖先检查差异，对不能在不削弱保护前提下统一的部署暂停上线，由运营方选择统一策略；不静默采用更宽松默认。
- 认证：保留现有单次登录、会话撤销、全端退出、首次改密与实时内省语义；密码匹配改官方 DelegatingPasswordEncoder/受控算法表，保留现有 bcrypt12 哈希，禁止启用 noop。不随本计划另换哈希算法。
- 自定义会话与协议层：本次**保留**必要的 PG 登录绑定、签发上限、撤销清理和 BFF 多身份隔离。只移除已取消需求产生的分支、提取重复校验；不以“代码多”为由全量替换 Provider 或删除会话表。
- 标准认证入口：租户解析后交标准认证组件完成密码匹配和账号检查；事务内重新检查租户/账号版本后才建立会话。状态在密码验证期间改变时拒绝签发，不新增第二套会话生命周期。
- 第三方登录：使用 Spring OAuth2 Client；保留旧设计的可信租户及外部身份绑定，不按同邮箱自动合并；用固定配置和标准重定向流程，不做提供方插件平台。

这组决定限制改造范围：本计划不是重写 IAM。若要求连账号/后台都不再研发，则选择完整开源产品替换并重新规划；不会同时维护本地密码库与另一套 IAM 密码库。

### 3.2 直接复用开源的清单

| 事项 | 复用对象 | 仍由框架承担 |
| --- | --- | --- |
| 密码认证 | Spring Security UserDetailsService / DaoAuthenticationProvider / DelegatingPasswordEncoder | 租户定位、用户状态、首次改密和失败审计 |
| 协议与第三方登录 | Spring Authorization Server / OAuth2 Client / Resource Server | 租户、应用权限和撤销适配；已有安全逻辑不盲删 |
| 浏览器会话 | Spring Session Redis（已经使用） | 必要的身份隔离与撤销关联；不另开发存储引擎 |
| 迁移 | Flyway；Alembic ScriptDirectory/command API | 受控入口、账号、串行执行和失败停止；不自写 revision 解析 |
| 服务与消息接入 | SCA/Nacos 官方 SDK、HTTPX、Spring AMQP/aio-pika | 统一约定、可信上下文、消息事务适配 |
| 发布 | Compose v2、Ansible community.docker | 有限固定 playbook、环境输入和可观察结果；不是通用发布平台 |

核对依据（组件能力说明，不代表本仓库已验证）：[密码存储](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html)、[标准密码认证](https://docs.spring.io/spring-security/reference/servlet/authentication/passwords/dao-authentication-provider.html)、[Spring Session](https://docs.spring.io/spring-session/reference/web-session.html)、[Alembic API](https://alembic.sqlalchemy.org/en/latest/api/script.html)、[Ansible Compose](https://docs.ansible.com/projects/ansible/latest/collections/community/docker/docker_compose_v2_module.html)。实施沿用当前锁定兼容版本，不因链接显示新版而全仓升级。

## 4. 新项目使用与交付材料

本节是待验证的接入成果要求，目标操作最终写入指南；下列拟新增入口目前不可宣称已可用。以普通资产项目说明，示例实体只用于证明接入，不属于 identity-service 或公共包。

### 4.1 开发者拿到什么

| 直接复用 | 项目复制后自行维护 | 项目自己开发 |
| --- | --- | --- |
| identity-service/api-gateway 镜像；platform-parent/foundation；ken-platform-sdk | examples 中独立工程；按版本提供的 config/infra/deploy 起始材料；最小 web 示例 | 资产等领域实体、业务迁移、接口/对象授权、页面；实际环境与第三方凭据 |

两种语言是选择，不是每个项目都必建两个业务服务。需要 Java/Python 协作时才复制两个。建议目标目录：

```text
asset-project/
├── services/
│   └── asset-service/       # Java 或 Python
├── web/                    # 有业务前端才保留
├── config/                 # 项目环境绑定和 Nacos 源
├── infra/                  # 自建依赖与资源初始化输入
├── deploy/                 # 应用 Compose、Nginx 和主机清单
├── pyproject.toml          # 运维工具环境；与业务 Python 工程分开
├── uv.lock                 # 与运行材料同版的工具依赖锁
├── framework-baseline.json # 发行版本、材料校验和；用于升级三方比较
└── docs/
```

框架仓库代码继续位于 framework/，不为精简移动整个仓库。拟新增的 examples/java/sample-service 与 examples/python/sample-service 分别是独立工程，examples/web 是业务演示；不用本地 parent relativePath 或 Python editable 依赖绕过发行物验证。

### 4.2 从创建到使用

1. **取同一发行版本**：复制所需示例与运维起始材料，锁定包版本及镜像；不复制身份/网关/SDK 源码。T-02 可使用本地候选制品库验证，最终 T-07 必须证明团队可获取发行物。
2. **填环境**：项目代码、环境、公开域名、服务名/发布地址、PG/Redis/Nacos 等绑定和秘密引用。秘密来自未入库文件；Nacos 仅接收允许集中调整的参数/路由；服务工程保存默认行为、配置类型、权限清单与业务迁移。
3. **准备依赖**：本地通过 infra 启动 PG/Redis/Nacos；使用消息才启动 RabbitMQ。有现成组件时跳过安装，仅核对资源和凭据。新增服务只增所需数据库/运行账号等资源，不能重建共享卷。
4. **准备基础服务**：先迁移身份库，再通过身份镜像的维护入口执行 bootstrap（初始管理员、平台/租户管理 BFF 客户端及指定服务的目录发布身份），随后启动 identity、gateway 和入口代理。bootstrap 不依赖在线 API；重复只核对、不重置密码。业务 BFF、内省与机器客户端后续登记，不重复创建管理客户端。失败停止后续步骤。
5. **接入业务**：业务库迁移、权限目录/应用 audience/客户端登记、网关显式路由，然后启动业务服务。登记是受限发布操作，不能向所有业务实例下发身份管理员凭据。不得要求未登记的服务先通过完整鉴权启动才能登记自身。
6. **使用后台**：平台创建租户；租户管理员开户、建立普通业务角色、勾选服务发布的权限并分配用户。新增权限不自动授出，管理页不改源码。平台负责应用/提供方配置，租户管理员不需要学习委派或模拟器。
7. **业务研发**：开发者写业务表与接口，声明如 asset:read/asset:update，使用 SDK 取得可信主体/事务；自行落实 owner_user_id 或本租户范围。缓存/文件需要时用统一租户命名和访问规则；前端自行处理页面/按钮表现。
8. **联调**：先全容器跑通，再替换一个业务实例为 IDE 进程。明确宿主/容器发布地址，不让调试实例混入其他环境；Java↔Python 用标准 HTTP/JSON，机器调用与用户委托有区别。
9. **部署**：Windows 本地开发与 Linux/WSL 控制机分工写清；Ansible 调用每台应用机的 Compose，按迁移→分批更新→健康检查执行。Compose 网络只作用单主机，跨主机用可达私网地址/端口。
10. **升级**：检查兼容范围与备份 → 构建并锁定目标制品 → 执行兼容迁移 → 更新所选应用 → 健康检查与业务烟测。迁移失败禁止更新应用。管理页随身份镜像升级，不重建业务前端；配置差异人工审阅，不覆盖项目改动；失败按兼容范围回退应用或执行受控数据恢复。

### 4.3 发行验收的关键约束

- 没有项目源码相对引用、手工数据库种子或测试专用认证夹具，新项目也能完成真实首次登录及业务调用。
- 纯 Java 与纯 Python 均能独立使用；Python 项目仍可复用 Java 身份/网关镜像，但不需要开发 Java 业务代码。
- 管理页固定功能是租户/用户/角色授权/应用接入/会话/审计/个人账号；删除委派/模拟不影响业务权限配置。
- 多节点指普通无状态业务 API 可扩容；请求内状态不跨节点假设、共享数据外置。通用 SSE 不缓冲及正确断连即可，不宣称支持业务事件持久回放或自动续跑。
- 不给固定容器数掩盖依赖：基础组合为身份、网关、PG、Redis、Nacos及所需入口代理；再增加实际业务服务，消息/对象存储按需。外部依赖可不在本项目启动容器；单点组件不冒充高可用。

### 4.4 发行清单与同机隔离

发行必须列出 Maven parent POM/foundation JAR、Python wheel、身份/网关镜像、所选 examples，以及同版 config/infra/deploy、根 pyproject.toml/uv.lock、校验和与升级说明。T-02 允许本地候选仓库及 Docker 镜像；不能依赖原源码目录或开发者已有 Maven 缓存。T-07 验证团队可获取发行物。

复制后的业务源码、环境和运行材料归项目维护；framework-baseline.json 保存原发行材料摘要。升级比较原基线、新基线和项目文件，显式吸收差异，不覆盖项目源码/秘密/卷。工具环境与业务依赖分别锁定。

项目 A/B、同一项目不同环境必须同时启动验证。Compose 项目/网络/卷由 project+environment 区分；不设置缺少环境的固定 container_name。宿主发布端口可配置；容器服务端口不变；Nacos API/gRPC 映射保持客户端端口偏移约束。已有卷/网络通过明确绑定保留，不因升级改名挂空卷。默认 RabbitMQ 关闭，纯 HTTP 路径不创建 Agent 数据库。
