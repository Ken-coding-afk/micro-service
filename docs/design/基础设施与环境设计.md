## 1. 依赖清单与启用条件

infra/compose.yaml 只定义第三方组件。deploy/compose.yaml 定义 identity、gateway、业务 API/Worker、Nginx。二者是独立 Compose 项目；本地通过明确创建的同机 external network 互通，连接别名固定，不能假设两个 Compose 项目默认网络相通。

| 组件 | 本地默认 | 测试/生产默认 | 初始化结果和持久化责任 |
| --- | --- | --- | --- |
| PostgreSQL 17 | 一个容器，开发命名卷 | 独立数据目录/卷，固定补丁，备份与 WAL 归档 | 每服务库、owner/migrator/runtime 角色；按数据库实例恢复 |
| Redis | 一个容器，独立开发凭证 | 独立实例，AOF everysec，默认 noeviction，设置内存上限和告警 | 登录/BFF 与缓存使用不同 key 前缀和受限账号；满内存写失败按依赖故障处理 |
| Nacos | 单节点、内置 Derby、持久卷 | 当前基础拓扑同为单节点持久化并启用鉴权；独立维护 | namespace、服务/配置凭证、配置摘要；不使用业务 PG 冒充原生 Nacos 存储 |
| RabbitMQ | 文档异步/聊天组合启用 | 独立持久卷、固定版本、资源告警 | vhost、发布/消费账号、与服务版本匹配的 durable 队列/交换机 |
| S3 对象存储 | 文档/附件示例使用明确的测试 endpoint；未配置时只跑不含附件的聊天 | 项目提供符合 S3 接口的服务或现有托管实例 | bucket、最小访问权限、保留与备份策略；不默认强加一个存储产品 |

纯同步 HTTP 示例不启动 RabbitMQ 和 Worker；聊天/文档任务示例必须启用。身份用户激活事件需要可靠发布时启用 Rabbit，未配置消费项目不能宣称业务资料初始化闭环已完成。Redis 不是唯一业务事实来源，AOF everysec 仍有丢失最近写入的窗口，不能保证登录会话零丢失；noeviction 避免静默淘汰会话，超过内存限制会拒绝部分写入，必须告警并按依赖故障处理。[Redis 持久化](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/)、[淘汰策略](https://redis.io/docs/latest/develop/reference/eviction/)

每项目/环境默认独立组件实例；同一项目的多个服务可共用 PG 实例，但不能共用数据库账号/任意跨库查询。若采用已有外部组件，则跳过相应容器安装，保留能力检查和本项目资源初始化；不同时启动一个闲置容器假装它是实际依赖。测试与生产不共用数据、消息 vhost 或凭据。

当前基础拓扑有单点，不宣称 HA；高可用涉及具体 PG/Redis/Rabbit/Nacos/入口拓扑、预算和故障验收，不是把 app 副本数改为 2。Nacos 内置 Derby 与外部 MySQL 部署方式以官方为准，不能因业务统一 PG 就添加未验证的存储插件。[Nacos 单机部署](https://nacos.io/en/docs/v3.0/manual/admin/deployment/deployment-standalone/)

## 2. 本地、测试与生产环境

| 项 | local | test | prod |
| --- | --- | --- | --- |
| 用途 | 首次运行、个人调试 | 集成、升级和故障验收 | 正式业务 |
| 数据与凭证 | 独立随机开发凭证、假数据 | 独立库/卷/namespace/vhost、脱敏数据 | 独立数据与秘密，禁止复制开发账号 |
| 应用运行 | 初次全容器，日常指定业务 IDE | 全部固定镜像 | 测试通过的同一镜像 digest |
| 基础设施 | 本机 Docker，按组合启用 | 独立服务器组件或明确外部实例 | 按环境清单安装/接入，独立维护 |
| 登录入口 | 显式 local loopback；内部/外部地址分开 | 实际 HTTPS 域名与真实代理 | 固定 HTTPS、内部信任与证书续期 |
| 数据保护 | 显式 local reset；普通启动不删卷 | 验证迁移与恢复样本 | 备份/WAL/恢复演练、受控发布 |
| 管理执行机 | Windows/Python/Docker 或 Linux | Linux/WSL Ansible 管理机 | 唯一授权的 Linux/WSL 管理入口 |

Ansible 不假设能原生运行在 Windows PowerShell；本地日常启动不要求 Ansible，服务器发布从 Linux/WSL 管理机执行。三种环境使用相同代码合同，差异通过环境配置与组件运行规格表达，不维护三份分叉业务代码。基础设施、地址与凭证不因应用镜像跨环境复用而共享。

## 3. 自建组件与外部实例接入

基础设施清单显式声明每个组件是 self_hosted 还是 external，按环境选择；组件模式不由“能否连接某端口”推断。infra/resources.yaml 保存本项目资源声明；各环境的 self_hosted/external 选择、实际 endpoint 和秘密引用统一来自 config/environments。资源声明只引用这些绑定，不重复保存第二份环境值。

| 模式 | 操作 | 验证 | 不允许的隐式行为 |
| --- | --- | --- | --- |
| self_hosted | 在指定 infra 主机启动锁定镜像和持久卷 | 版本/卷/网络/健康、管理员与运行身份边界 | 应用 deploy 顺带替换镜像 |
| external | 使用已提供服务，跳过对应 Compose 服务 | 协议/TLS/账号权限/本项目资源、备份责任方 | 外部不可用时偷偷改连本地临时实例 |

外部数据库可能不允许应用方建库。此时由组件所有者预创建清单中的库与角色，初始化入口执行只读/最小权限核对并记录“外部提供”；不要求把共享集群管理员密码交给项目。PG/Rabbit/Nacos/Redis 可分别采用不同模式，交付清单必须能准确显示实际使用者。

## 4. 组件运行配置与持久化

| 组件 | 固定运行材料 | 本地与服务器的差异 | 必须验证 |
| --- | --- | --- | --- |
| PG | 锁定镜像、postgres 参数、数据/WAL/备份路径、健康检查 | local 命名卷；服务器明确卷/UID、备份目的地和容量 | 运行账号无 DDL/BYPASSRLS；可恢复 |
| Redis | 内存上限、AOF、noeviction、ACL、数据目录 | local 随项目；服务器独立凭据与告警 | 会话写入失败不放行，key 前缀/ACL有效 |
| Nacos | 服务端配置、鉴权密钥、持久卷、端口清单 | local 每人独立；服务器环境独立 | 配置源与服务端配置分开；注册/读取/发布权限符合冻结版本 |
| Rabbit | 数据卷、vhost/账号、服务声明的拓扑、内存/磁盘阈值 | local 按组合启用；服务器有积压和磁盘告警 | 发布确认、持久化及消费者权限 |
| S3 | endpoint/bucket/访问身份与策略 | local 可用测试实例；prod 独立数据/凭据 | 对象归属、大小和下载授权；备份责任明确 |

镜像使用 digest；组件进程支持的环境变量、挂载路径和实际端口由兼容冻结任务按所选版本核实，不凭经验硬编码。主机 NTP、可用磁盘、文件权限、日志轮转、CPU/内存与连接上限是安装前检查项。

## 5. 数据库、账号及命名空间初始化

| 阶段 | 执行入口归属 | 使用身份 | 必须产生的结果 |
| --- | --- | --- | --- |
| 安装/启动组件 | infra/compose.yaml，受 Ansible infra.yaml 调用 | 主机维护身份 | 进程健康、卷可写、版本/网络正确 |
| 创建环境资源 | infra/init/run.py 及声明清单 | 限时使用 PG/Nacos/Rabbit 管理凭证 | 服务数据库/角色、namespace、vhost/账号；不创建业务表 |
| 发布应用配置 | config/publish.py | Nacos 配置发布身份 | 对应环境的参数可读及摘要记录 |
| 迁移 schema | 所属服务镜像的 migrate 入口 | 该服务迁移账号 | Flyway/Alembic/RLS/约束达到目标版本 |
| 初始化身份应用 | identity 镜像 bootstrap 入口 | 本服务受控初始化身份 | 初始平台账号、固定管理客户端和内置权限 |
| 启动身份服务 | deploy 中固定镜像 | identity runtime 账号 | readiness、内省/授权和管理 API 可用 |
| 发布业务权限 | 服务 permissions.yaml，经 sync-permissions.py 调用身份 API | 受限权限目录发布凭证 | 目录建立，新权限不自动授予 |
| 登记业务客户端/资源服务 | 管理页面或同等受保护管理 API | 有权管理应用的管理员 | BFF、机器、资源内省客户端及允许范围就绪；禁止将权限目录发布凭证用于任意客户端扩权 |
| 启动业务应用 | deploy 或本地 IDE | 对应 runtime 账号 | 可注册、可鉴权；项目用户按角色访问 |

PG 初始化为每服务创建 NOLOGIN owner、独立 migrator 和 runtime；迁移具备该服务 DDL 能力，runtime 无 DDL/超级用户/BYPASSRLS。owner/表默认权限在迁移中检查，不能让新增表丢失 runtime 授权或 RLS。Agent API/Worker 共享同服务库，受限调度访问按[聊天Agent多节点设计·部署角色与数据归属](聊天Agent多节点设计.md#d11)处理。PG 管理凭证不挂进常驻应用。

初始化按明确资源名幂等执行：不存在才创建，存在则核对归属和权限；重复执行不改密码、不清库、不吞掉不一致。凭证变更走独立轮换；未知资源或归属冲突停止。不能只依赖空数据卷首次启动时运行的 SQL，因为后续新增服务还需要增量建库和账号。业务迁移另有数据库锁，不能用“初始化已完成”跳过迁移历史。

## 6. 幂等、增量与部分失败恢复

资源声明通过绑定取得 project_code、environment，包含逻辑服务所有者和资源名称。声明 schema 固定包含 resource_id、component、owner_service、name_binding、management（create/verify）、账号角色及授权引用、必要的 depends_on；禁止含秘密值、任意 SQL 或任意 shell。create 只在具备授权时创建缺失资源；verify 只核对外部预建对象。运行名称从绑定解析后校验项目/环境和允许字符，先展示脱敏差异再执行。初始化对每项记录 ABSENT/CREATED/VERIFIED/CONFLICT/FAILED；结果中不记录密码。现有资源先比对预期归属和权限，不能因为同名就默认属于本项目。

新增 document-service 时只创建该服务的新库/账号及消息资源，不重新初始化 identity。部分资源创建成功后失败，保留已成功资源，下一次先核对再继续；不自动删除已创建对象来“回滚整个环境”。不存在的数据库可以创建；已存在却版本/归属不明的数据库不能自动 baseline。

prepare-local 只生成未存在的本地秘密和网络；resources 只创建环境资源；服务 migrate 只改自己的 schema。凭据轮换、资源删除和 local reset 都是独立显式动作。初始化入口以本地文件锁/服务器发布锁避免并发操作相同环境。

## 7. 网络、访问身份与端口

同一主机 infra 与应用是两个独立 Compose 项目，显式连接项目专属 external network。容器访问网络别名；宿主机访问仅映射到 loopback 的开发端口。服务实际发布地址由所在运行模式决定，规则见配置与服务发现文档。

跨服务器使用私网 DNS/IP 与映射端口，按消费方放行；Nacos 附加客户端通信端口也纳入清单。互联网只允许应用入口端口，数据库/队列/配置控制面不公开。Docker 端口发布可能影响主机防火墙的实际路径，验收从另一台主机实测。

组件管理员凭据仅在初始化/维护阶段提供，按需临时挂载；常驻业务进程只拿本服务身份。共享 PG 实例不等于共享账号，Redis 的数据库编号不构成访问控制边界。

## 8. 数据维护、组件升级与开发重置

本地卷可长期保留；清理仅针对当前项目 local 的明确卷，独立显式 reset 动作不进入日常启动/发布。测试/生产使用明确宿主机数据路径与运行 UID 权限；应用版本目录、镜像与持久数据分开。禁止发布时 down -v、volume prune 或用新镜像挂不兼容旧数据目录。

维护资料至少包括：版本/digest、网络端口、卷路径、资源上限、健康检查、账号/秘密引用、备份和恢复步骤、责任人。PG 备份恢复合同见[数据库迁移与升级设计·迁移所有权、账号和执行入口](数据库迁移与升级设计.md#d14)；Rabbit/Nacos 数据和定义、身份签名密钥、对象存储配置纳入恢复清单。组件升级是独立维护任务，不由普通应用 deploy 顺带更新。

资源部署成功的条件是实际连接和权限检查通过，而非仅有容器 running。检查包括从消费主机连到目标、运行账号不能 DDL、数据库可恢复、控制面不对公网开放；未具备真实服务器时只可记录本地验证。

## 9. 项目拓扑与容器数量

下面是自建组件、单实例、无自托管模型/监控/对象存储时的常驻数量；使用外部托管组件时本机容器数相应减少，但逻辑依赖仍存在。

| 项目组合 | 基础组件 | 框架与入口 | 业务运行角色 | 常驻合计 |
| --- | --- | --- | --- | --- |
| 单个同步 Java 或 Python 服务 | PG、Redis、Nacos：3 | identity、gateway、Nginx：3 | 业务 API：1 | 7 |
| 文档异步分析 | PG、Redis、Nacos、Rabbit：4 | identity、gateway、Nginx：3 | document API、analysis API、analysis Worker：3 | 10 |
| 单节点聊天 | PG、Redis、Nacos、Rabbit：4 | identity、gateway、Nginx：3 | Agent API、Agent Worker：2 | 9 |
| 双 API/双 Worker 聊天 | 同上：4 | 同上：3 | Agent API×2、Worker×2：4 | 11 |

Nginx 托管业务静态页面，管理静态页面内置 identity，不各加容器。初始化、迁移和构建容器执行后退出，不计常驻。单节点依赖、入口存在单点；本表不构成 HA 保证。文档/附件示例另要求 S3 endpoint，若自建对象存储其容器与数据必须另外计入。
