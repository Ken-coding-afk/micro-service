## 1. 管理对象、入口与使用者

功能边界遵循[已确认范围](01-总体架构与工程结构设计.md#decisions)：固定平台/租户管理，不交付委派、模拟、邀请/开放注册或租户安全策略覆盖。

管理界面属于 identity-service 产品能力，源码放 `identity-service/admin`，构建后的静态资源随该服务同一镜像交付。每个项目部署同一发行镜像，连接自己的配置和数据库，即可使用；不需要启动项目业务 Web，也不需要复制用户、角色、权限页面。基础服务仍是 identity-service 与 api-gateway 两个，管理页面不增加运行容器。

平台管理员指当前独立项目的管理员，不是跨项目账号中心。平台主体管理租户生命周期、初始管理员、平台应用及安全底线；租户管理员只管理当前租户的账号、角色及会话与身份审计；普通用户进入个人账号页面管理自身资料、凭证与授权。平台主体不能冒充租户用户访问业务数据。

框架不建立菜单表、角色菜单关系、动态业务页面注册或页面组件授权模型。权限目录只表达业务资源、操作和数据范围。管理产品自己的固定导航仅帮助使用者找到功能；能否读取或修改由对应后端权限决定。项目业务前端的页面、按钮和导航显示由项目自行实现，框架仅提供身份与有效权限 API，不强制前端框架或权限指令。

## 2. 源码目录、构建与登录入口

以下均为拟新增路径，后端保持既有单 Maven 模块结构：

```text
identity-service/
├── pom.xml
├── Dockerfile                      # Node 构建阶段 + Java 构建阶段 + JRE 运行阶段
├── admin/
│   ├── package.json                # private: true；只构建本产品页面
│   ├── pnpm-lock.yaml
│   ├── vite.config.ts
│   ├── src/
│   │   ├── app/                    # 独立应用入口、固定路由、布局、身份上下文
│   │   ├── pages/
│   │   │   ├── tenants/
│   │   │   ├── users/
│   │   │   ├── roles/
│   │   │   ├── permissions/         # 目录、角色授权编辑、有效权限及来源
│   │   │   ├── applications/        # OAuth 应用、机器身份
│   │   │   ├── providers/
│   │   │   ├── sessions/
│   │   │   ├── security/
│   │   │   ├── audit/
│   │   │   └── account/
│   │   ├── api/                    # 仅调用身份服务 API
│   │   └── components/             # 权限选择器、范围选择器、差异预览等内部组件
│   └── tests/                      # 管理流程、权限配置、会话和升级用例
└── src/main/
    ├── java/com/ken/platform/identity/
    │   ├── controller/             # tenant/user/role/permission/oauth/session/security/audit
    │   ├── service/                # 对应职责；业务规则与事务
    │   └── dal/                    # 对应持久化；不依赖业务数据库
    └── resources/
        ├── db/migration/
        └── templates/              # 登录、首次改密、密码重置、OAuth 授权同意
examples/web/
├── src/app/                        # 业务前端自己的装配与登录跳转
├── src/api/                        # BFF、/me 和业务 API 演示
├── src/views/documents/
├── src/views/items/
└── package.json / pnpm-lock.yaml
```

框架构建阶段在 admin 目录执行锁定依赖安装、类型检查及 Vite 应用构建，输出拷入 Java 的生成资源目录 `target/generated-resources/static/identity/admin/` 后打包。生成文件不提交到源码 resources；生产 JRE 镜像不携带 Node 或开发服务器。仅框架维护者构建管理页面，项目团队直接拉取镜像。

外部固定入口为 `/identity/admin/`，个人账号入口为 `/identity/admin/account`；Gateway 显式转发该前缀至 identity-service，不与项目业务前端的 SPA fallback 混用。只对管理页面的已知页面路径回退 index，API/不存在的资源返回原有错误。静态首页和非敏感品牌配置可匿名加载；任何身份信息、目录和管理动作必须认证授权。

管理界面通过 Gateway BFF 访问身份 API，不持有浏览器 access token 或客户端秘密。平台与租户分别使用 `identity-admin-platform`、`identity-admin-tenant` OAuth 客户端和各自 `/bff/identity/platform/`、`/bff/identity/tenant/` 路径命名空间，独立 Cookie 名、CSRF 状态与服务端会话键；业务 Web 继续使用 `web-bff`。回调属于相应命名空间且精确登记，登录上下文绑定主体类型和租户。BFF 根据固定端点命名空间选择会话，不由 tenant_id/header 猜测；管理接口在 BFF 侧分别挂载到这两个前缀下的 `api/`，转发至身份服务 `/api/v1/identity/` 下对应 API，租户管理客户端不能取得平台 scope。角色切换/租户切换显式重新认证，刷新页面不改变主体归属。

静态首页可公开不代表接口公开。所有写请求验证 CSRF，401 引导对应登录入口，403 显示拒绝且不自动重试写入。退出撤销对应授权并清理该命名空间会话，另提供明确的全端退出；Cookie 删除不代替后端授权撤销。登录与授权同意仍由身份服务模板完成，不能依赖业务 Web 存在。

## 3. 完整功能清单与敏感操作

| 页面 / 功能 | 用户可以完成的操作 | 权限与失败边界 |
| --- | --- | --- |
| 平台管理员维护 | 初始化后修改本人凭证；现有平台管理员新增/启停其他平台管理员、查看管理审计 | 平台账号独立于租户账号；保留最后一个有效平台管理员；不由租户角色授权产生 |
| 租户管理 | 创建、查询、修改名称/期限、启用/停用；创建初始管理员；发起管理员交接并查看完成结果 | 平台主体；停用使该租户新认证/内省失效；交接先建立有效接任者再移除原管理员，不展示现有密码 |
| 用户管理 | 租户内查询/分页、创建、编辑基础资料、启停、分配角色、发起密码重置、查询有效权限 | 租户主体；相同用户名可存在于不同租户；不包含业务身份字段；重置后旧授权失效 |
| 角色管理 | 创建、复制、改名称/说明、启停、查询成员、授予操作和数据范围 | 创建/复制由受保护租户管理员执行；受保护角色不可复制出保护能力；非空角色先移除成员再删除 |
| 权限目录 | 查看服务/领域/资源/操作、说明、支持范围、状态、来源发行版本 | 管理页只读；由受限发布流程同步，不能手输任意编码制造权限 |
| 角色授权编辑 | 搜索、分组、逐项或批量选择、选择数据范围、只看已授权、保存前差异预览 | 按 [多租户与权限体系设计·权限目录、固定管理边界与并发规则](04-多租户与权限体系设计.md#delegation) 的目录版本、对象保护和并发检查执行；没有权限的操作默认拒绝 |
| 有效权限与授权解释 | 查询角色来源与范围，选择应用/资源/操作查看允许或拒绝原因，预览授权变更 | 使用统一计算器；区分全量角色授权与应用实际授权；不宣称已验证具体业务对象 |
| OAuth2/OIDC 应用 | 登记应用、配置类型、准确回调/退出地址、授权方式、audience/scopes、启停与凭据轮换 | 仅平台管理员登记；应用绑定明确租户和获准范围；public 客户端没有秘密 |
| 机器身份 | 创建调用身份、设置单租户/audience/scopes/允许操作，轮换或撤销凭据 | 不是创建假用户；跨租户 Worker 属于平台受限技术身份，租户管理员不能创建 |
| 第三方登录 | 登录模板显示已配置方式；会话页进入本人绑定/解绑流程 | 提供方与适用租户由运维维护固定 Spring 配置，按认证设计验证；不建设在线编辑/连接测试页面 |
| 会话管理 | 查询登录设备摘要、时间、关联应用；撤销指定会话、用户全端退出 | 租户管理员需会话管理权限；普通用户只能管理自己；撤销不只是删 Redis 键 |
| 安全设置 | 按[安全策略字段](05-认证与OAuth2设计.md#security-policy)配置密码最小长度、弱密码保护、登录失败阈值/锁定时长和会话期限，查看项目有效值 | 项目统一策略，仅平台管理员维护；令牌协议、密钥算法及数据隔离不能通过页面改变 |
| 审计查询 | 按时间/操作者/动作/对象/结果筛选，查看脱敏前后差异和 request_id | 租户只读本租户；平台只读平台控制操作，不通过审计查看租户业务正文；页面不提供修改审计 |
| 登录及授权流程 | 平台/租户登录、首次改密、重置密码、第三方登录、OAuth 授权确认、拒绝及退出 | 登录绑定确定租户；初始密码必须更换后才可发业务授权；回调/state/nonce/PKCE 按 [认证与OAuth2设计·组件、协议端点与接入登记](05-认证与OAuth2设计.md#protocol) |
| 个人账号 | 修改显示名和本人密码、查看/撤销本人会话、绑定/解绑第三方账号、查询/撤销已同意应用授权 | 绑定/解绑和凭据操作要求近期重新认证；至少保留一种有效登录方式；不允许自改租户或角色 |

账号仅管理员创建，公开注册和邀请不在当前交付。密码重置采用一次性凭证，有效期 15 分钟、散列存储、单次消费并限速；无发送渠道则由受保护管理员受控交付，不能宣称邮件已发送。改密/重置更新 auth_version 并撤销旧授权，凭证不进日志/审计。

安全策略保存后对新认证与后续会话检查生效：缩短会话期限按原创建/最后活动时间重新计算，不延长已过期会话；密码设置规则变化只约束下次设置密码，不尝试检查散列中的旧密码。界面展示生效时间和影响；机器 token 有效期、协议 grant 及密钥策略沿用[认证与OAuth2设计](05-认证与OAuth2设计.md#protocol)，不允许租户突破。登录限流 Redis 不可用时返回服务不可用，不关闭保护。

第三方配置启动校验限制 HTTPS、允许主机及网络出口；内网提供方必须由运维显式加入允许列表，禁止访问云元数据地址。提供方密钥使用受控文件引用，不提供返回秘密的查询；客户端新秘密仅创建/轮换时一次性返回，丢失后重新轮换。

文档、知识库、聊天运营、Agent 编排、具体资源共享成员、学号/资质等业务资料均由项目实现。管理产品不加载项目组件、不查询业务数据库、不提供部署或容器运维页面。业务资料以 tenant_id + user_id 关联；无需给通用用户页增加每项目分支。

应用页 `/platform/clients` 同时提供服务 audience 登记、用户/机器客户端登记、版本化修改、启停及一次性秘密轮换。固定管理客户端由维护入口管理，页面只读。轮换接口为 POST `/api/v1/identity/platform/oauth-clients/{id}/secret:rotate`，携带 version；同事务更新协议凭据和策略版本，使旧秘密与旧授权失效；公开客户端拒绝轮换。响应秘密只存当前页面内存，关闭、离开或更换身份清除；409 或结果未知保留草稿并阻止直接重复提交，先查询当前版本。安全策略页 `/platform/security` 读取并修改项目统一策略，使用现有乐观版本检查，不提供租户覆盖。

## 4. 权限配置的页面交互

用户有效角色与来源查询保留；不提供独立授权模拟与拟申请 scopes 的预览。角色保存前的集合差异展示保留。

对象保护、固定管理身份和并发判断由[多租户设计](04-多租户与权限体系设计.md#delegation)定义，页面展示服务端允许动作，不计算另一套权限。

**创建角色并授权。** 进入当前租户的角色列表，创建名称、说明和业务角色标识；选择业务应用，再按资源分组勾选操作。每项展示权限编码、名称、说明、风险级别、支持的数据范围和目录版本。只有服务端允许的项可选；不支持的组合不出现为可保存选项。选择 SELF/TENANT 等范围时展示含义和影响对象。新权限默认为未选中。保存前展示增加、移除和范围扩大/缩小的差异，提交版本号；409 后保留本地草稿并要求重新加载差异，禁止自动覆盖。

**分配已有角色。** 从用户详情或角色成员页执行；显示目标账号所属租户、账号状态、已有角色、拟增减角色，以及哪些项因受保护对象限制不可修改。批量操作先返回逐项预检结果，最终提交仍重新授权。部分失败逐项展示，不把全部成员标为成功。业务权限分配成功不意味着操作者获得该业务的读取权。

不提供委派设置页面。普通业务角色不能承载身份管理能力；受保护管理员通过专用管理入口维护。

**检查用户权限。** 在用户详情查看当前有效角色授权和范围/来源；本人 `/me` 查看当前应用实际权限。结果显示评估时间，不承诺具体业务对象可访问。

**权限目录变更。** 发布流程登记新目录，页面展示新增、弃用和不兼容项；管理员明确修改角色后才产生授权。目录不能通过页面任意新增一条与服务代码无关的权限。目录更新记录可定位发行版本，已引用权限不能静默删除。

页面对 401 引导对应身份域重新登录；403 显示动作无权；409 显示版本冲突；400 显示具体字段/规则；503 提示依赖暂不可用并保留未提交输入。写请求失败不自动重放，秘密只显示一次且离开后不可恢复。

## 5. 页面与接口、持久化的对应

所有下列 API 都属于 identity-service；外部经 [身份管理界面设计·源码目录、构建与登录入口](06-身份管理界面设计.md#delivery) 的 BFF 访问，业务前端只需登录/退出、`/me` 和业务 API。约定前缀为 `/api/v1/identity`，以下是拟新增资源入口：

| 入口 | 输入 / 输出及检查 |
| --- | --- |
| `/platform/admins`、`/platform/tenants` | 平台账号/租户的分页、创建、版本化修改和启停；初始化/交接管理员使用独立动作并审计 |
| `/users`、`/users/{id}/roles`、`/roles` | 只操作会话租户；分页上限 100；提交当前记录 version；角色分配检查整个角色权限及目标管理范围与 protected 状态 |
| `/permissions`、`/role-permissions/{role_id}` | 返回可授予目录、catalog_version/role_version、明确授权集合；不含页面或组件信息 |
| `/users/{id}/effective-permissions` | 管理者查看目标账号全量有效角色授权、来源及范围，标记 view=ROLE_GRANTS；需查询权限及目标管理范围，不作为业务调用凭据 |
| `/me` | 仅返回当前登录应用可用信息与权限，标记 view=APPLICATION_EFFECTIVE；client_id 来自已验证 token/BFF 会话，按 token scopes 与客户端策略过滤；按 audience 分组，不接收浏览器指定任意 client_id；身份服务从本地 Authorization 记录取受验证的客户端/token 上下文重新计算，不把它自身的单 audience 内省结果误作全应用权限 |
| `/platform/oauth-clients` | 平台管理员维护应用；租户入口不提供对应管理能力，查询不返回秘密；提供方固定配置不经过此管理 API |
| `/sessions`、`/sessions/{id}:revoke`、`/users/{id}:sign-out-all` | 查询和撤销；按主体/租户检查，重复撤销幂等；指定会话不能扩大为其他用户全端退出 |
| `/platform/security-policy` | 平台管理员 GET/PUT 项目统一安全策略及 version；租户入口关闭 |
| `/audits`、`/platform/audits` | 限定主体范围的分页只读查询、脱敏差异、动作结果；无删除/修改 API |
| `/me/sessions`、`/me/consents` | 查询本人信息及显式撤销动作；外部身份绑定由认证设计的登录/会话模板处理；不得接受可替换 user_id 的请求以改变操作对象 |
| `/admin-config` | 仅返回 project_display_name、纯文本标题、同源 logo_url 和 API major；不包含精确发行版本、秘密、内网地址或任意可执行扩展；精确版本仅受保护诊断入口可见 |

管理动作使用固定内置身份权限并要求受保护管理员身份。租户管理员管理本租户用户、普通角色/授权、会话和身份审计；应用与安全策略只由平台管理；提供方由运维按固定配置发布。普通角色不可配置 identity 管理权限。管理员分配业务权限不代表其自动拥有该权限。

页面使用的实体、版本及归属以[身份实体设计](04-多租户与权限体系设计.md#entities)为准；安全策略字段以[认证设计](05-认证与OAuth2设计.md#security-policy)为准，页面不自行增设数据库规则。

会话撤销、敏感操作幂等和秘密响应丢失处理统一引用[Token 与会话生命周期](05-认证与OAuth2设计.md#tokens)。页面展示处理中/失败及重试结果，不宣称删 Cookie 就完成全端撤销。

授权/凭据修改与审计的事务规则由认证设计定义；列表不展示秘密，页面提交成功后重新读取服务端版本。

实际权限与来源复用[内省计算](05-认证与OAuth2设计.md#introspection)，不提供模拟 API；详细角色来源仅向受权管理者展示。

统一计算器输出功能权限和 SELF/TENANT 范围；例如允许 `document:read=SELF` 只能说明可读取本人文档，具体文档属于谁、是否归档、是否可删除仍由 document-service 查询并判断。角色差异预览展示预计授权变化，最终保存重查版本并生成实际审计；不能用旧预览替代提交检查。账号/租户/角色/客户端策略变更必须有对应的解释用例。

<a id="integration"></a>

## 6. 新项目直接复用与业务前端接入

接入顺序以[首次安装顺序](09-应用部署与运维设计.md#first-install)为准。项目使用原版 identity-service 镜像，配置 config/environments 的域名/issuer/秘密引用及 config/nacos/identity-service.yaml 的非敏感品牌参数；基础应用初始化后即可管理，无需业务 Web。账号授权、客户端精确回调属于身份数据库登记，不混入品牌配置。

项目服务发布权限目录后，同一管理页自动展示本项目的资源/操作/范围；业务团队不修改管理页面源码。业务自定义资料留在项目页，以 tenant_id/user_id 关联；业务资料初始化由项目自己实现，不依赖框架承诺的激活事件。管理入口链接由业务产品决定，链接本身不授予权限。

定制只允许显示名、同源 Logo 和声明的主题变量；不加载项目组件、脚本或前端插件。通用身份能力变化由框架统一发行；项目 Fork 需要自行维护差异与升级兼容。

<a id="upgrade"></a>

## 7. 升级、缓存与兼容

| 变更 | 框架维护者交付 | 项目团队操作 | 是否重建业务 Web |
| --- | --- | --- | --- |
| 管理页修复或样式调整 | 同版后端与页面的 identity-service 新镜像、摘要和发行说明 | 更新镜像 digest，测试管理流程后分批替换 | 否 |
| 身份字段/授权流程变化 | 新镜像、Flyway 迁移、配置变更、旧版 API 兼容范围 | 备份与兼容检查 → 独立迁移 → 更新镜像 → 身份与业务授权烟测 | API 兼容时否 |
| 新业务资源/操作 | 业务服务镜像及版本化权限清单 | 同步目录，人工审核角色授权；不会自动扩大现有授权 | 只在业务界面自身有变更时需要 |
| 公共后端接入包变化 | Maven/Python 依赖与兼容矩阵 | 仅升级受影响服务的依赖、构建并验证 | 否 |
| 身份 API 不兼容升级 | 新 major、调用方迁移说明、窗口和恢复限制 | 明确升级 Gateway/SDK/业务调用方，不能只替换身份镜像 | 调用合同受影响时需要 |
| examples 更新 | 同标签示例与可审阅差异 | 手工吸收所需业务示例改动，不覆盖已复制项目 | 由项目改动决定 |

管理 UI 与身份后端不分别选版本；发行清单记录 identity_image_digest、admin_build_id、identity_api_major、schema_revision、Gateway/SDK 兼容范围与配置校验值。身份接口小版本遵循增加字段/端点不破坏旧调用者，移除或改变语义使用新 major 和明确迁移窗口；实际支持组合必须验收，不承诺任意旧版本永久兼容。

为避免滚动发布时旧页面调用新后端，admin index 与运行配置使用 no-cache，带内容摘要的静态资源使用不可变缓存。默认管理发布执行短维护窗口：阻止新管理写入、排空、切换到同一版本实例后恢复；不在新旧静态资源之间随机负载均衡。已登录页面通过受保护的兼容检查（API major、admin_build_id）提示刷新；匿名 /admin-config 不返回精确 build id。版本不匹配时提示刷新，不自动重放尚未确认的写请求。若要求无停机静态发布，必须另行证明版本路由/资源保留方案；当前明确不承诺零中断。

数据库先按 [数据库迁移与升级设计·迁移所有权、账号和执行入口](10-数据库迁移与升级设计.md#ownership) 执行 expand 兼容迁移，再部署镜像；失败停止发布。仅当旧镜像仍兼容现有 schema/API 时回退旧镜像，管理页面随之回退。数据库不自动降级，存在破坏性迁移则按隔离恢复与数据补偿方案执行。升级不能重跑 bootstrap 覆盖密码、清空角色、重建用户 ID、重置自定义角色或重新授予全部权限。

举例：两个项目都使用身份镜像 1.0.0，框架修复授权页面后发布 1.0.1。各项目更新自己的发行清单并分别发布身份服务；管理页随镜像更新，原有租户/角色/授权保留，项目 web 目录和已部署业务前端摘要保持不变。这里的正式版本是流程示例；当前候选发行状态与验证见实施计划。
