## 1. 配置分类与唯一主要来源

工具源码位于固定 vendor；项目 config/development.yaml 登记服务语言/目录/入口，POM/pyproject 仍是依赖权威。工具通过显式项目根或输入路径读取项目声明，状态只写项目 .local。派生绑定仅在文件仍等于上次生成摘要时更新；用户改过则拒绝并指出路径，秘密不覆盖。

服务源码声明配置类型、校验规则和安全默认值；config 保存环境绑定和 Nacos 配置源；秘密由本机受控文件/既有密钥系统提供；业务与身份数据通过 API 保存在各自数据库。

| 内容 | 唯一主要来源 | 变更行为 |
| --- | --- | --- |
| 服务名、监听端口、注册地址、APP_ENV、项目编码 | config/environments 的环境变量 | 重启对应进程 |
| Nacos 地址、namespace、鉴权凭据引用 | 环境绑定 + secret 文件 | 在首次读取 Nacos 之前可用 |
| PG/Redis/Rabbit/S3 的 endpoint、库名/vhost、用户名 | 环境绑定 | 重启；不同时在 Nacos 配置第二份 |
| 密码、client_secret、模型 API Key、私钥 | 单独 secret 文件或已有密钥系统 | 按明确轮换流程加载，禁止进 Git/Nacos |
| issuer、内部身份地址、客户端 ID、TLS 信任与回调来源 | 环境绑定；客户端实际授权登记在身份数据库 | 按身份配置变更/重启，不开放运行时任意切换 |
| 超时、池大小、日志级别、技术开关、运行并发上限 | config/nacos 的版本化源 → Nacos | 仅热更新白名单可在线应用，其余重启 |
| Gateway 公开路由 | config/nacos/api-gateway.yaml → Nacos | 预校验后重启 Gateway；旧路由格式迁移使用维护窗口，同版配置/制品切换 |
| 配置字段与默认值、权限码、API、消息拓扑声明、迁移 | 所属服务源码/制品 | 随代码版本发布，不由 Nacos 临时改接口 |
| 用户、租户、角色、OAuth 应用、租户额度与业务开关 | 身份/业务数据库，通过对应管理 API | 不作为 Nacos 配置维护 |
| PG/Redis/Nacos 自己的参数、卷、资源限制 | infra 中组件配置 | 独立基础设施维护 |
| 入口域名/证书引用、容器副本/资源、镜像 digest | 环境绑定与 deploy 声明 | 校验后加载或应用发布 |

Nacos 技术上可以保存数据库地址；本设计将地址归于环境绑定，避免 IDE、容器和跨主机寻址差异污染同一个服务参数文件。连接池参数仍属于运行参数。模型供应商 endpoint 属于环境绑定；随 Agent 代码的模型默认名称/提示词版本随发行，租户选择和额度保存在业务数据库，秘密独立注入。

## 2. 服务配置类型与校验合同

Java 使用类型化配置属性，Python 使用 Pydantic Settings；公共配置合同随 sdk/java、sdk/python 发布，业务专有字段由所属服务声明。每个字段声明：名称、类型、来源分类、必填性、默认值、校验规则、是否支持热更新及失败行为。

| 字段示例 | 来源 | 校验 | 生效 |
| --- | --- | --- | --- |
| SERVICE_NAME | 环境绑定 | 必须匹配所选服务与发行声明 | 启动 |
| PG_HOST/PORT、DB_NAME/DB_USER | 环境绑定 | 端口范围、名称非空；启动实际连接确认 | 重启 |
| DB_PASSWORD_SECRET_FILE | Secret 文件引用 | 文件存在、可读、非空；日志不输出内容 | 轮换/重启 |
| HTTP 连接/响应预算 | Nacos 参数 | 正数；不得突破调用链剩余 deadline | 重启，除非对应实现声明安全热更 |
| 技术准入并发上限 | 服务 Nacos 参数 | 正整数；未配置表示不启用该保护 | Java Sentinel JSON 动态；Python 重启；均不抢占在途请求 |
| 权限码、消息 schema | 服务制品 | 与目录/版本相符 | 发布代码，不能通过 Nacos 改语义 |

环境字段不接受 Nacos 同名覆盖；secret 值不接受普通环境明文回退；仅 local 组件初始化的随机开发凭据可保存在忽略的 environment.env，测试/生产必须使用 *_SECRET_FILE。应用拒绝来源错误和未知字段，而不是“最后读到谁就信谁”。共享 Nacos 参数仅可被声明允许的服务级参数覆盖，覆盖结果连同来源摘要对运维可见；秘密只能显示是否已配置。

服务专有参数放在该服务 Data ID 的 `business` mapping，不能放入 application-shared。框架继续拒绝未知公共字段；business 的领域字段不进入框架白名单，由 Java 业务类型或 Python Pydantic 模型负责类型、范围和未知字段校验，启动检查在注册发现之前执行。框架递归拒绝秘密与环境绑定字段，键名使用小写下划线；不在 Nacos 保存连接凭据。快照只读，business 变更必须重启，不参与热更新。示例为 `business.max_page_size: 50`，两个服务各自校验 20—100；不是框架新增统一分页策略。

组件字段：Java/Python 均支持 `http.max_connections`（默认 64，正整数）；`http.max_keepalive_connections` 仅 Python 使用（默认 32，正整数且不大于总连接数），Java 不接受这一 HTTPX 专属字段。Reactor Netty 限制每目标连接池与等待数量，HTTPX 限制所持客户端总连接数；两种参数不宣称完全等价。Python 服务专用 `concurrency.inbound_limit` 可省略或正整数，`outbound_limits` 为最多 64 个逻辑服务名到正整数的映射；禁止放入共享配置。连接池字段、Python 并发及原生路由均重启生效。

原生网关只接受 `id/uri/predicates/filters/metadata`；当前业务入口为一个 Path API 前缀，metadata 仅 audience 与可选 streaming，过滤器仅已定义的 RequestRateLimiter。框架验证安全边界，绑定与执行交给 SCG；不支持任意 SpEL、Retry、动态外部 URI 或隐式公共 API。旧 gateway.routes 显式拒绝迁移。

## 3. 环境文件与秘密注入

config/environments 只提交非敏感样例、允许公开的环境标识及主机清单；实际 environment.env、local.env、local-host.env 与 secret 文件均忽略。镜像内不固化某项目凭证或生产地址。Compose 明确加载 env-file；IDE/终端由固定 dev.ps1/dev.sh 启动入口或提供的运行配置导出变量，Java 不会自动读取 .env。

环境合同至少包括 PROJECT_CODE、APP_ENV、SERVICE_NAME、SERVICE_BIND_HOST/PORT、SERVICE_ADVERTISE_HOST/PORT、NACOS_SERVER_ADDR/NAMESPACE、PUBLIC_ORIGIN、IDENTITY_INTERNAL_ORIGIN、PG_HOST/PORT、各服务 DB_NAME/DB_USER、REDIS_HOST/PORT、RABBIT_HOST/PORT/VHOST、S3_ENDPOINT，以及对应 *_SECRET_FILE。服务级数据库名、客户端身份和秘密只映射给所需服务；不把整台机器的秘密目录挂给每个容器。

local.env 是本地全容器绑定；local-host.env 只覆盖在宿主机运行的指定服务的连接地址/监听/注册地址。其允许字段清单由 SDK 和启动入口固定验证，不覆盖 Nacos 技术策略或令牌安全规则。秘密在宿主机为受限文件，容器以 /run/secrets 挂载；真实凭证不放命令行参数、日志或发布清单。Compose secrets 是文件挂载机制，不自动提供集中加密保管和轮换。[Docker secrets](https://docs.docker.com/compose/how-tos/use-secrets/)

<a id="nacos"></a>

## 4. Nacos 命名、隔离与服务端配置

每个项目/环境一个 namespace，例如 asset-project-local、asset-project-test、asset-project-prod；每位开发者默认独立本机 Nacos，不在共享 namespace 注册同名调试服务。Group 固定 DEFAULT_GROUP；Data ID 为 application-shared.yaml、各 service-name.yaml；启用 Sentinel 的 Java 服务另有 service-name-sentinel-flow.json 和 service-name-sentinel-degrade.json。共享配置只放真正共同的非敏感参数，服务配置只覆盖声明允许的同名共享运行参数；禁止在 Nacos 定义环境绑定或秘密字段。

infra/nacos 保存 Nacos 服务端的端口、鉴权、存储配置；config/nacos 保存启动之后发布给应用的参数。Nacos 不能先读取自己才能启动，也不负责启动 PG 或创建应用数据库。

<a id="startup"></a>

## 5. 应用配置加载与就绪顺序

应用启动顺序固定：加载环境绑定/秘密 → 校验 Nacos 连接信息 → 读取共享和本服务配置 → 按类型合同合并运行参数 → 校验必需字段 → 创建依赖客户端 → 检查 schema/身份条件 → 注册 ready 实例。首次配置缺失或不合法不进入 ready。运行时丢失 Nacos 保留已验证配置并报警；不回退到另一环境或忽略安全策略。

配置客户端和业务客户端分别有生命周期；先验证完整配置再创建连接池。运行时配置审计只能返回摘要及非敏感字段，不能提供任意读取 secret 的诊断端点。

<a id="publishing"></a>

## 6. 配置发布、漂移与回退

配置源在 Git 中审阅，由 scripts/config/publish.py 使用发布凭证同步指定 namespace/Data ID，比较旧摘要并拒绝覆盖未知变更，记录新摘要/来源版本。应用运行身份不具有发布权限。发布账号与运行账号分别绑定 NACOS_PUBLISH_USER/NACOS_RUNTIME_USER 及相应秘密引用，只授本 namespace 的配置发布或配置读取/发现权限；初始化不自动授予 console 管理能力。控制台只用于查询和受控应急；应急修改必须回写源文件并记录差异，下一次正常发布检测到漂移先停止。不能运行时从项目仓库拉取配置。

配置可追溯版本指发布摘要，不假设多个 Data ID 原子切换。存在跨服务兼容依赖时按发行顺序滚动重启相关服务，readiness 报告实际配置摘要；单个 Data ID 成功不代表整批成功。回退只恢复与当前镜像和 schema 兼容的已保存配置。

<a id="refresh"></a>

## 7. 热更新与重启边界

日志和已有观测开关保持原热更行为；Sentinel 规则按以下动态规则合同执行，Gateway 路由、HTTP 池和 Python 并发变更需要重启。不得把所有参数统一热更或统一要求重启。

### 规则来源、配置字段与生效

Java 使用 Sentinel 原生 FlowRule/DegradeRule JSON，不再保留原 Java 组件的实例配置，也不建立跨语言 protection DSL。Git 中规则源经现有发布工具进入 Nacos；官方 NacosDataSource 负责订阅，框架只负责来源、资源命名、整份校验与启动检查。Dashboard 可独立评估，本次不部署、不作为运行依赖，也不开发规则控制台。

沿用项目/环境 namespace 和 DEFAULT_GROUP，新增以下文件/Data ID（拟新增，当前发布工具尚不支持）：

```text
config/nacos/
├── api-gateway.yaml
├── sample-java-service.yaml
├── sample-java-service-sentinel-flow.json
├── sample-java-service-sentinel-degrade.json
└── sample-python-service.yaml
```

Java 服务 YAML 使用原生开关 `spring.cloud.sentinel.enabled: true`。启用后由框架按服务名确定上述两个 Data ID，复用现有 Nacos 地址、namespace、凭据与 TLS 绑定，不在规则文件重复填写秘密；缺省未启用则不创建治理数据源。DataSource 的启动、关闭归服务 runtime，避免监听器和客户端泄漏。官方数据源日志可能格式化连接 Properties，传入的 Properties 必须对 toString 脱敏，并在测试中验证哨兵密码不进入日志。

FlowRule 示例（入站 64、出站 32，数字仅用于演示）：

```json
[
  {"resource":"http.inbound","grade":0,"count":64,"strategy":0,"controlBehavior":0,"clusterMode":false},
  {"resource":"http.outbound/sample-python-service","grade":0,"count":32,"strategy":0,"controlBehavior":0,"clusterMode":false}
]
```

DegradeRule 示例：

```json
[
  {"resource":"http.outbound/sample-python-service","grade":1,"count":0.5,"timeWindow":20,"minRequestAmount":10,"statIntervalMs":10000}
]
```

本次接受上述字段，`limitApp` 仅允许默认来源，规则资源必须匹配固定入站名或合法逻辑服务名；禁用正则资源/集群模式，不开放额外规则策略或任意异常类配置。FlowRule 的并发 count 必须为正整数；DegradeRule 依组件范围验证，重复资源规则拒绝。将 JSON 先完整校验再交给官方管理器，不能让原生“跳过非法项”导致保护悄悄消失。

| 配置 | 行为 | 生效 |
| --- | --- | --- |
| Gateway 原生路由及 Redis 令牌桶参数 | 保持协作设计 #gateway 的原生配置和范围校验 | 重启 Gateway |
| Sentinel FlowRule / DegradeRule | 同一 Data ID 整份验证、整份替换；不同规则种类独立生效 | 原生 Nacos 监听动态更新，不重启 |
| Sentinel 启用开关、Nacos 连接与资源代码 | 随服务启动确定 | 重启/发版 |
| Python `concurrency.inbound_limit`、`concurrency.outbound_limits` | 缺省关闭，声明值必须是正整数；按指定依赖启用 | 重启 Python 服务 |
| SDK `http.max_connections: 64`、`max_keepalive_connections: 32` | 正整数且 keepalive ≤ max；Python 为客户端总池，Java 为远端池，不宣称相同总量 | 重启 |
| Java pendingAcquireMaxCount=64；两语言池等待上限 1 秒 | 等待同时受剩余 deadline 限制；池等待失败映射 DEPENDENCY_BUSY | 固定框架策略，不另开无限队列 |

Spring/Sentinel 原生字段允许其 camelCase/连字符格式，不改成另一套别名。其他公共参数继续现有来源和字段规则；Python 不加载 Java 规则文件。Gateway 原生 filter 的允许范围仍为 Path、lb://、RequestRateLimiter，安全/BFF 固定装配；不允许 Retry、任意 SpEL 或绕过鉴权的重写。

**动态更新及失败处理：**

1. 启用 Sentinel 时，首次必须读到两个有效 JSON 数组，完成校验后才能注册/ready；缺失、空白、非法配置或无法读取时启动失败，不把空配置当成默认放行。显式 `[]` 表示有意停用该类规则，发布必须展示删除差异。
2. 运行中收到合法更新，由对应官方 RuleManager 替换该类规则；非法、空白、删除或连接中断保留最后有效规则并记录错误，不发布空数组替代。首次没有有效规则时不使用不明来源本地缓存绕过启动校验。启动使用已有 NacosConfigReader 的网络读取完成核验；不能只依赖会吞初始异常/读取缓存的 NacosDataSource 构造器。
3. 两个 Data ID **不是跨文档事务**，多节点监听也是最终收敛。分别输出有效规则摘要/加载时间；发布验收核对所有目标实例的 flow/degrade 摘要，不把“写入 Nacos 成功”当作“全部节点生效”。不为此建设自研版本协调服务。
4. 调低并发阈值只影响新准入，不取消在途请求；修改/删除熔断规则可能重建状态和统计窗口，遵循组件语义，不承诺继承 OPEN 状态。回退规则是发布旧有效内容；无需重启，但同样要验证各实例已收敛。
5. 路由、HTTP 池、Python 并发等重启字段仍保持旧快照并提示需重启；只有 Sentinel 原生规则使用上述动态通道。Redis 桶按原 key 延续/过期，不清空 Redis。

<a id="service-discovery"></a>

## 8. 服务注册、寻址与退出

Nacos 管配置和发现，不执行网络转发或鉴权。Java 用 SCA，Python 用官方 SDK；实例采用 PROJECT_CODE/APP_ENV 对应 namespace 和同服务名。API readiness 完成后注册，停机先摘除再排空；liveness 不因短暂依赖异常引发重启风暴。客户端订阅加周期校准，最后确认超过 60 秒停止使用陈旧列表，连接失败及时剔除并受 deadline 约束；冻结版本必须实测能达成该边界。

监听端口与 SERVICE_ADVERTISE_HOST/PORT 独立，跨主机必须公布调用者能到达的私网端点；不能假设 Compose bridge 跨主机连通。SDK 退出时注销并关闭客户端；同一服务的多个副本不使用相同地址/端口，Worker 不混入 API 发现列表。[Docker Compose 网络](https://docs.docker.com/compose/how-tos/networking/)、[Nacos Python SDK](https://github.com/nacos-group/nacos-sdk-python)

<a id="failures"></a>

## 9. 失败处理与运维证据

| 故障 | 启动时 | 运行时 / 恢复 |
| --- | --- | --- |
| Nacos 地址或凭据错误 | 连接失败，不 ready | 报警；不连接其他 namespace 或默认公共实例 |
| 必需 Data ID 缺失 | 列出缺项，停止应用就绪 | 现有已验证快照保留，等待受控修复 |
| 非法类型/范围/来源 | 拒绝整个候选快照 | 保留旧快照，记录拒绝字段与版本，不泄露值 |
| Nacos 短暂失联 | 无首次快照则不能启动 | 保留配置；服务发现按其陈旧时限独立处理 |
| 发布一批配置部分失败 | 不把整批标成功 | 记录每个 Data ID 摘要；按兼容条件续跑或回退 |
| 控制台人工修改造成漂移 | 发布前检查到则停止覆盖 | 应急变更回写 Git，确认实际基线后恢复正常发布 |
| 实例退出未能注销 | 不适用 | 发现校准和调用失败剔除共同兜底，不保证零错误请求 |

配置发布账号与应用运行账号分离。发布结果记录 project/environment/namespace、Data ID、来源制品、前后摘要、操作 ID 和时间。Nacos 不是业务数据库：租户权限、注册策略、租户套餐、Agent 用户配置不能通过普通配置发布改变。
