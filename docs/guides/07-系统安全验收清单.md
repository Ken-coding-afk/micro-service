# 系统安全验收清单

本页用于项目候选发行的系统验证，不是“已经通过”的报告。当前 Docker 及真实环境验收暂停；单元/假传输结果见实施计划或本项目 CI 记录，不能据此声称通过渗透测试。只在明确授权的隔离项目/测试域名运行动态验证，不攻击生产或不属于本项目的系统。

## 1. 前提和记录

记录源码提交、配置/镜像摘要、目标域名与白名单、两个独立测试租户、普通用户/租户管理员/平台管理员及受限机器客户端。秘密通过受控文件提供，不写入用例文档、截图或报告。记录每项请求与脱敏响应、request_id、预期/实际、成功或未验证；无环境不是通过。

浏览器、入口、网关、资源服务与 identity 需要同一次发行；PG/Redis/Rabbit 各用隔离资源。依赖漏洞/秘密扫描是供应链检查，不能替代下面的授权和协议验证。

## 2. 必须覆盖的动态矩阵

| 场景 | 操作/输入 | 必须观察到的结果 |
| --- | --- | --- |
| 跨租户读写 | A 账号请求 B 的真实对象ID，篡改 tenant/user header，GET/PUT/DELETE各覆盖 | 拒绝或不泄漏存在性的404；B的数据不变；不能只测空表 |
| 数据范围 | SELF 用户访问同租户他人记录，再用 TENANT 权限用户访问 | SELF 拒绝，TENANT 按实际角色允许；缓存和对象键也不能跨租户 |
| 权限提升 | 普通用户调用管理员 API；租户管理员调用平台入口；修改角色/客户端超出允许范围 | 403，状态无变化；拒绝审计可按 request_id 查询 |
| 授权交集 | scope、audience、permission 分别缺一个；机器身份缺 allowed_tenant | 任意一项不足均拒绝，不因成功登录绕过 |
| 撤销和停用 | 已登录后撤角色、停账号/租户、撤 token/会话，再发新请求 | 成功内省不缓存，新内省反映已提交变更；在途请求不承诺回滚 |
| 内省故障 | 身份服务不可达、错误协议、超时 | 503，不能降级成匿名或信任JWT自行解码；恢复后按真实状态判断 |
| 登录枚举 | 不存在账号、错误密码、停用身份；同一输入格式/次数比较 | 不因存在性返回不同敏感内容；检查状态、正文、Cookie与重定向；耗时不声称恒定 |
| BFF/CSRF | 缺CSRF和跨站修改；混用platform/tenant会话；伪造代理身份 | 拒绝，不将管理会话带入另一个入口，不透传浏览器伪造身份 |
| OAuth/OIDC | 非登记redirect、PKCE不匹配、重复code、state/nonce不匹配、错误client secret | 协议拒绝，保持标准错误；不能重放授权码或窃取另一客户端令牌 |
| Grafana边界 | 匿名/租户/无scope/撤权访问页面和查询API，伪造X-WEBAUTH，后端直连，跨站POST | 均拒绝；合法平台访问成功。Viewer只读不等于租户隔离；监控关闭不影响登录 |
| 数据库运行权限 | 错库/错用户、owner或可继承owner、CREATE/BYPASSRLS/super角色；断库和恢复 | 注册前拒绝不安全身份；动态readiness故障DOWN、恢复再校验；实际RLS读写隔离成立 |
| MQ来源与幂等 | 重复event_id、相同ID不同body、假producer/错误版本、业务事务失败 | 重复不重复落库；冲突/假来源隔离；失败不确认成功。业务副作用单独检查 |
| 错误泄露 | 畸形JSON、参数错、404/405、业务异常、DB/上游失败 | 统一业务错误体和request_id；无秘密、SQL、堆栈、上游正文；OAuth/已提交流例外明确 |
| 预算与保护 | 超时、并发耗尽、依赖断路、取消请求后重新请求 | 有界拒绝、许可释放，无身份/日志串扰；不盲目重试写操作 |
| 入口与头 | TLS/HTTP、伪造Forwarded、跨来源访问、静态/错误页、指标端口公网探测 | HSTS仅TLS；代理头只信任已登记来源；CSP/CSRF有效；指标与Grafana无绕过公网入口 |

## 3. 不依赖 Docker 的检查

SDK 定向测试覆盖并发上下文、纯鉴权/错误协议、DB返回值/异常/超时模型；网关使用 loopback 假上游验证凭据剥离与权限矩阵；前端组件测试验证入口显示。这些可以提前运行，但不能证明真实PG角色、浏览器cookie策略或主机防火墙有效。

恢复运行验收后，按第2节逐项执行，发现失败先保留证据再修复；只复验受影响项及必要回归。可使用成熟HTTP/浏览器工具和受控扫描器辅助，自动扫描不能代替业务越权用例。未经确认不扫描任意地址、不清库、不关安全控制来通过用例。

## 4. 发行结论

结果逐项为“通过/失败/未验证”，不把未运行标为跳过即通过。C3必须包含真实双租户/撤权/代理边界证据；性能、多机和备份恢复另行记录。失败项阻断其覆盖的发行声明；尚无环境时可提交开发代码，但不得把其标签或提交描述为已通过生产安全验收。
