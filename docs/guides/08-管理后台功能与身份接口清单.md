# 管理后台功能与身份接口清单

> 基线 D-20261029-01；2026-10-29。后台上一轮验证见[后台改造计划](../plans/2026-10-28-项目基础管理后台与开放接口改造-plan.md)；当前分页对齐的实际进度见[API与交付计划](../plans/2026-10-29-API约定与最小发行验收及同仓服务-plan.md)，不以旧证据替代本轮验收。

## 1. 后台定位与操作顺序

这是项目研发和平台管理员使用的基础管理后台，只提供平台管理员登录，按 PC 桌面使用设计。客户业务页面由各项目开发；身份与管理 API 可供自建页面调用。

单租户项目先创建一个 `default` 租户即可。只有一个可用租户时自动进入该租户用户页；存在多个租户时显式选择，页面 URL 保存目标，不把目标租户写进平台管理员 token。平台管理员和业务用户是不同账号，不自动互相取得权限。

推荐顺序：创建租户 → 创建组织树 → 创建用户并分组 → 创建业务权限 → 建角色并分配权限 → 给用户或组分配角色 → 接入业务接口 → 查审计及监控。

| 主模块 | 可操作功能 | 主要接口 | 平台权限 |
| --- | --- | --- | --- |
| 租户管理 | 新建、查找、启停、名称/有效期；新建租户同时生成首位租户管理员 | P `/tenants`、`/tenants/{id}` | platform:tenant:read/manage |
| 用户管理 | 分页、搜索、状态/组筛选；完整资料创建/编辑；启停、重置密码；直接角色、所属组、有效权限来源 | T `/users`、`/users/{id}`、`/profile`、`/roles`、`/groups`、`/effective-permissions`、`/password-reset` | platform:identity:read/manage |
| 用户组 | 公司/部门/团队树；新增、编辑、移动、启停、空组删除；直接/下级成员；组角色 | T `/groups` 及子资源 | platform:identity:read/manage |
| 角色管理 | 新增/编辑/启停/空角色删除；权限授权；直接用户与关联组分别查看 | T `/roles`、`/role-permissions/{id}` | platform:identity:read/manage |
| 权限管理 | 项目级目录；服务/来源/状态过滤；手工新增及展示字段编辑/启停；查看角色引用 | P `/permissions`、`/service-audiences` | platform:permission:read/manage；引用另需 platform:identity:read |
| 审计日志 | 平台操作和显式选择租户的身份操作；筛选、分页、事件详情，敏感资料脱敏 | P `/audits`；T `/audits` | platform:audit:read；租户审计另需 platform:identity:read |
| 服务监控 | 固定最近5分钟采集状态、请求率、5xx比例、P95；按需展开 Grafana 详情 | M `/availability`、`/services` | platform:monitoring:read |

系统设置收纳接入应用、安全策略和平台管理员；个人账号用于本人密码、授权、会话管理。租户会话治理接口保留。旧租户后台页面及 `/bff/identity/tenant/**` 返回404，不提供租户后台登录；租户身份业务 API 继续提供。

## 2. API 地址与认证

- P = `/api/v1/identity/platform`。
- T = P + `/tenants/{managementTenant}/identity`，平台身份必须显式指定目标。
- U = `/api/v1/identity`，租户从已验证的 USER token 取得，不能接受调用方任意 tenant_id 扩权。
- M = `/api/v1/platform/monitoring`，由 api-gateway 提供。

外部调用先由平台登记 OAuth 应用，使用 Authorization Code + S256 PKCE 换取 Bearer access token。外部平台管理应用登记为 PLATFORM，并申请对应的 `platform.tenants`、`platform.identity`、`platform.permissions`、`platform.audit`、`platform.monitoring`。客户端类型或 scope 不是管理员资格，身份服务仍验证当前平台用户权限、audience、令牌授权上限和近期认证。USER/SERVICE 应用不能申请平台管理 scope。

所有 HTTP API 都可由自建应用直接调用，不依赖后台 Cookie 或 BFF CSRF。浏览器内置后台通过自己的 BFF 会话及 CSRF 调用同一服务用例。U 管理入口要求对应 identity.* scope、操作权限和受保护租户管理员资格，不能用它跨租户。

租户用户组 API 使用 `identity.groups`；查询组成员、查询或修改用户所属组还需 `identity.users`；查询组角色及角色关联组还需 `identity.roles`。平台显式目标接口统一使用 `platform.identity`。网关自带身份 API 固定路由，不需要业务项目重复配置这条路由。

本地开发 OpenAPI：身份服务端口 `/v3/api-docs/identity-management` 及 `/swagger-ui/index.html`。生产环境不开放文档入口；公开 API 通过网关访问。监控 API 由网关实现，方法与返回合同见本页，不在 identity-service 的 OpenAPI 中。

身份服务文档用于查看请求、响应和授权要求，不自动注册或发放管理身份。外部应用仍须先登记自己的 OAuth 客户端；不能使用业务服务的 Swagger 客户端申请平台管理权限。

既有能力继续使用以下接口；组织和手工目录的完整子资源列在后文。表中 T/U 表示平台显式目标和租户自身均有入口，并非两套实现。

| 能力 | 方法与相对路径 | 所需 scope |
| --- | --- | --- |
| 租户 | P GET/POST `/tenants`；GET/PUT `/tenants/{id}` | platform.tenants |
| 用户 | T/U GET/POST `/users`；GET/PUT `/users/{id}`；PUT `/users/{id}/profile` | 平台 platform.identity；租户 identity.users |
| 用户直接角色及有效权限 | T/U GET/PUT `/users/{id}/roles`；GET `/users/{id}/effective-permissions` | 平台 platform.identity；租户按用户/角色操作权限取交集 |
| 重置密码 | T/U POST `/users/{id}/password-reset` | 平台 platform.identity；租户 identity.users |
| 角色 | T/U GET/POST `/roles`；PUT/DELETE `/roles/{id}`；POST `/roles/{id}:copy`；GET `/roles/{id}/members` | 平台 platform.identity；租户 identity.roles |
| 角色授权 | T/U GET/PUT `/role-permissions/{id}`；GET `/permissions` | 平台 platform.identity；租户 identity.roles / identity.permissions |
| 会话治理 | T/U GET `/sessions`；POST `/sessions/{id}:revoke`、`/users/{id}:sign-out-all` | 平台 platform.identity；租户 identity.sessions |
| 审计 | P GET `/audits`；T/U GET `/audits` | 平台 platform.audit，目标租户另需 platform.identity；租户 identity.audit |
| 平台管理员 | P GET/POST `/admins`；GET/PUT `/admins/{id}` | platform.admins |
| 接入应用 | P GET/POST `/oauth-clients`；GET/PUT `/oauth-clients/{id}`；POST `/oauth-clients/{id}/secret:rotate` | platform.clients |
| 安全策略 | P GET/PUT `/security-policy` | platform.security |
| 服务登记 | P POST `/service-audiences` | platform.clients |
| 本人账号 | U GET/PUT `/me/profile`；GET `/me/sessions`、`/me/consents`；POST `/me/password`、`/me/sessions/{id}:revoke`、`/me/sessions:sign-out-all`、`/me/consents/{clientId}:revoke` | 当前有效用户身份及本人边界 |
| 监控摘要 | M GET `/availability`、`/services` | platform.monitoring |

scope 只是客户端/token 上限，仍须满足具体操作权限；受保护管理员、近期认证及版本条件不因拥有 scope 而取消。服务自动发布权限使用既有内部机器接口，不作为浏览器匿名接口暴露；手工维护使用本页 P 接口。

## 3. 资料、组织和授权合同

用户字段为 username、display_name、real_name、employee_no、contact_email、phone、avatar_url、description，以及只读 status/version/创建更新时间/last_login_at/group_names。工号租户内唯一；普通联系邮箱不代表验证邮箱；头像地址只保存引用，不提供上传服务。

`POST T/U /users` 接受资料及 `groups: [{id, version}]`、`roles: [{id, version}]`，全部同事务写入。响应返回 id 和一次性初始密码；密码不会在用户详情重现。`PUT /users/{id}/profile` 是完整资料替换，必带 version/display_name，遗漏可选字段表示清空，不能夹带密码或验证邮箱字段。

| 方法与路径（T/U） | 请求合同 | 输出/约束 |
| --- | --- | --- |
| GET `/groups` | parent_id、q、page、size；缺省查根；非空 q 全树搜索 | items、has_more、organization_version；节点带完整路径、数量、版本、effective_status |
| GET `/groups/{id}` | id | 节点资料、直接/下级成员数、后代数、角色数 |
| POST `/groups` | code、name、parent_id、description、sort（默认0）、organization_version | 新节点；code 不可变，租户内唯一 |
| PUT `/groups/{id}` | version、organization_version、name、description、sort、status | 当前节点与版本；状态变化影响整条后代授权链 |
| POST `/groups/{id}:move` | version、organization_version、parent_id、sort | 拒绝跨租户、环、停用父链及版本过期 |
| DELETE `/groups/{id}` | version、organization_version | 必须没有子组、直接成员和角色；否则409并说明引用数 |
| GET `/groups/{id}/members` | q、page、size、include_descendants | 去重用户，direct 与 group_paths 区分来源 |
| POST `/groups/{id}/members:add` / `members:remove` | group_version、users: [{id, version}]，1～100项 | 全批校验、原子操作；不能移除仅有下级来源的成员 |
| GET/PUT `/groups/{id}/roles` | 替换时 group_version、roles: [{id, version}] | 只绑定普通角色，禁止管理员保护角色 |
| GET/PUT `/users/{id}/groups` | 替换时 user_version、groups: [{id, version}] | 只修改直接加入的组；多组或空组均允许 |
| GET `/roles/{id}/groups` | page、size | 角色关联组；角色 members 仍只列直接用户 |

组织只是成员和角色的组织结构，不是部门数据权限引擎。用户权限 = 直接角色 + 直接加入且有效的组角色；同权限去重、保留来源。父节点的角色不会自动下传。父节点停用使子树组授权失效，但用户账号和直接角色不受影响。最终业务权限还要经过客户端、token scope、资源 audience 等交集。

业务数据范围仍只有 SELF/TENANT，由业务接口按可信身份落 SQL 条件；不能通过组层级自行扩大到“本部门/下级部门”。Java 的 `@RequirePermission` 与 Python 的 `require_permission` 不需要另外读取用户组，两者从统一内省取得当前结果，见[SDK参考](06-SDK使用参考.md)。

## 4. 业务权限目录与角色分配

权限目录全项目共用，各租户独立配置角色。来源为 BUILTIN（框架）、PUBLISHED（服务清单）或 MANUAL（手工）。界面只能修改 MANUAL 的名称、分组、资源名称、说明、排序及启停。编码、所属服务、资源/动作编码、OAuth scope、数据范围创建后固定，语义错误应停用并新建正确项。

| 方法与路径（P） | 合同 |
| --- | --- |
| GET `/service-audiences` | 已登记且可选择的业务服务，排除 identity-service |
| GET `/permissions` | owner_service/group_code/source/status/q/page/size，返回 catalog_version |
| GET `/permissions/{code}` | 定义、来源、can_edit、目录版本、角色/有效用户影响数量 |
| POST `/permissions` | code/name/owner_service/group_code/group_name/resource_code/resource_name/action_code/oauth_scope/supported_data_scopes/description/sort/catalog_version；仅业务 TENANT 权限 |
| PUT `/permissions/{code}` | name/group_code/group_name/resource_name/description/sort/status/catalog_version；非 MANUAL 拒绝 |
| GET `/permissions/{code}/roles` | 可选 tenant_id、page/size；租户、角色、授权范围 |

新建权限不会自动赋给用户。随后使用 T/U `PUT /role-permissions/{roleId}` 提交 role_version、catalog_version、grants: [{permission_code, data_scope}]，再分配角色给用户或组。停用权限后下一次内省剔除该项；重新启用时原角色引用仍保留，界面应明确提示。服务发布不能覆盖 MANUAL 或 BUILTIN。

## 5. 外部调用与错误处理

例如 Python 使用 `httpx`：

```python
response = client.get(
    f"{origin}/api/v1/identity/platform/tenants/{tenant_id}/identity/groups",
    headers={"Authorization": f"Bearer {access_token}"},
    params={"page": 0, "size": 25},
)
response.raise_for_status()
groups = response.json()["data"]
```

Java 使用标准 HttpClient：

```java
var request = HttpRequest.newBuilder(URI.create(origin
    + "/api/v1/identity/platform/tenants/" + tenantId + "/identity/groups?page=0&size=25"))
    .header("Authorization", "Bearer " + accessToken).GET().build();
var response = client.send(request, HttpResponse.BodyHandlers.ofString());
```

上例只展示已获得 access token 后的调用。OAuth 客户端登记、登录授权及刷新必须由调用项目完成；不得把管理秘密放进浏览器代码。

通用响应 `{code,message,data,request_id}`；分页遵循[公共HTTP合同](../design/07-Java与Python协作设计.md#http)：page默认0、size默认25；响应包含items/page/size/has_more，业务扩展字段保留。写入带当前对象/目录/组织版本。创建用户、组织、权限带 `X-Request-Id` 实现同请求幂等；结果不明先回读，不能无条件重试秘密签发。

| 状态 | 调用方操作 |
| --- | --- |
| 400 | 修正字段/类型，不重试相同错误请求 |
| 401 | 更新合法登录凭据；不要把空列表当成功 |
| 403 | 检查主体、scope、权限、租户状态及近期认证；需要时重新认证 |
| 404 | 目标不存在或当前身份不可见；监控未启用另有 MONITORING_DISABLED |
| 409 | 回读当前版本和引用，人工核对后提交；不覆盖别人修改 |
| 503 | 身份/监控上游暂不可用；保留草稿，写入结果不明确时先回读 |
