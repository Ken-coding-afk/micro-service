## 1. 调试前提与两种模式

先按[新项目接入指南](01-新项目接入指南.md)执行 scripts/init.py --env local --services all，默认 PG/Redis/Nacos、identity、gateway、nginx 运行在容器，两业务直接用 scripts/dev.py 启动宿主进程；全容器是发布验收路径，不是 IDE 的前置步骤。

每个开发者默认独立 local 依赖和 namespace。共享测试环境不得注册个人 IDE 实例；否则 Gateway 可能把其他人的请求路由到个人电脑。调试某个基础服务属于框架维护场景，使用本项目对应模块，项目已包含基础服务源码。

下面的命令使用[部署设计定义的固定入口与参数](../design/09-应用部署与运维设计.md#execution-entrypoints)，使用固定 vendor 内的 dev.py 校验合同；scripts/dev.py 负责必要构建/冻结安装再调用，不自动做数据库迁移。

<a id="addressing"></a>

## 2. 地址、issuer、回调和容器连通

地址与模式规则由[基础设施设计](../design/03-基础设施与环境设计.md#local-development)定义，Cookie/issuer 的 local 例外由[认证设计](../design/05-认证与OAuth2设计.md#origins)定义。此处按规则操作，不另定义安全例外。

先从 `.local/environment.env` 核对 PUBLIC_ORIGIN 和 IDENTITY_INTERNAL_ORIGIN。浏览器打开前者；从 Gateway 容器验证后者可达。切 IDE 时只修改 local-host 文件中允许的宿主地址、监听及注册地址；登录回调仍以原 PUBLIC_ORIGIN 为准。随后分别验证容器到 IDE、IDE 到依赖、浏览器经入口到业务三条路径，不能以本机 curl 成功代替。

<a id="switching"></a>

## 3. 宿主绑定

init 生成每服务 .local/runtime/<服务>.env 和 <服务>-host.env。服务运行只加载自己的秘密；工具环境在 .local/tools-venv，不进入业务环境。容器与宿主均需能访问所选 DEV_HOST；Docker Desktop 默认名称无法从宿主解析时显式传 --dev-host 私网IP。工具不会修改 hosts 或防火墙。已有容器实例应先按明确 Compose 服务名停止，再启动同名宿主实例，不按端口杀进程。

<a id="java"></a>

## 4. Java

IDE 导入项目根 pom.xml；命令 python scripts/dev.py equipment-service 自动构建必要 reactor 依赖并运行。源码调试从项目根打开 VS Code，F5 使用共享 launch 配置；Maven wrapper 在项目根，SDK 由 reactor 一起编译。

<a id="python"></a>

## 5. Python

python scripts/dev.py inspection-service 冻结安装服务独立锁，再启动 console entry。IDE 选择本服务 .venv 解释器；框架 SDK 以本项目 ../../sdk/python 路径 editable，业务依赖变更只在本服务 uv add/lock。命令行加 --reload 时同时监视服务 src 和 sdk/python/src；F5 断点调试保持关闭热重载，不同时启动两个占用同一端口的进程。生产镜像为非 editable 安装。不要让 UV_PROJECT_ENVIRONMENT 指到工具环境后执行业务 uv sync。

## 6. 业务前端热更新与身份页维护

生成项目的 web 默认是静态 HTML/JavaScript，由 Nginx 直接托管，不需要 pnpm 或 Vite。若业务后续引入 Vite，项目自行维护前端依赖锁，并在本地 Nginx 中明确增加页面与 HMR 代理；当前创建器不自动配置该代理。浏览器仍从 PUBLIC_ORIGIN 打开页面，BFF/API/identity 路径继续走 Gateway，避免端口变化破坏 OAuth 精确回调和 Cookie。

修改身份管理页面是框架维护工作：在 services/identity-service/admin 中安装/检查/构建，验证产物被 Java 镜像打包。项目自己的 web 不引入管理 npm 包，也不复制管理员用户/角色页面。

框架维护者使用 Node **24.13.0**、pnpm **11.12.0**；依赖版本与完整性锁定在 package.json/pnpm-lock.yaml，安装不运行依赖生命周期脚本。在 `services/identity-service/admin/` 的 PowerShell 执行（测试文件按当前改动选择，下面是个人账号范围）：

```powershell
pnpm.cmd install --frozen-lockfile --ignore-scripts
pnpm.cmd exec vitest run tests/identity-api.test.ts tests/account-page.test.ts
pnpm.cmd run verify:build
```

`verify:build` 执行 vue-tsc、零警告 ESLint/Prettier 和 Vite 生产构建；输出位于 `services/identity-service/target/generated-resources/static/identity/admin/`，生成文件不提交。完成本次 Java 定向测试后，在 仓库根 打包可用 `./mvnw.cmd -B -pl :identity-service -am package '-Dmaven.jar.forceCreation=true' '-DskipTests'`；这个命令只打包，不代表 Java 测试通过。Maven 会再次核对冻结安装、前端检查/构建，并要求生成首页存在。身份镜像先用固定 Node 镜像构建界面，再在 Java 构建阶段复制产物；最终 JRE 不需要 Node/pnpm，业务项目使用已验证发行镜像即可。

通过同一 PUBLIC_ORIGIN 打开 `/identity/admin/` 或 `/identity/admin/account`。选择平台或租户入口，租户填写组织代码；账号密码、首次改密在身份服务模板内完成，再回到管理界面。个人页管理显示名、密码、本人会话和应用同意；写入使用当前 BFF CSRF，401 重新登录，403 显示拒绝，409 保留草稿并对比当前资料，结果未知不自动重试。页面路径之外的未知静态文件和 API 不回退成首页。调试 Vite 时也必须保留同源 Gateway/BFF 路径，不能用开发端口替换已登记回调。

验收包括：热更新可用；登录、刷新、退出可用；业务 SPA fallback 不吞 identity/API 路由；普通用户调用无权管理的接口仍被服务端拒绝。匿名入口和个人账号页面不授予管理权限。仅页面显示“登录成功”不能替代会话和后端授权检查。

## 7. 测试数据与定向验证

本地数据通过身份管理 API/页面和业务 API 建立，示例提供可重复的开发数据入口。数据只能写入声明的 local 环境，必须有明显保护；不允许给生产自动建立测试租户。开发数据不改变迁移历史，也不包含真实用户隐私。

定向验证按改动选择：Java 服务执行其模块/测试过滤；Python 在该服务目录执行对应 pytest 文件；前端执行受影响组件/流程检查。完成当前实现后集中运行相关测试及适用 lint/typecheck/build，不默认跑整个框架套件。

身份/租户变更必须验证失败路径。只运行受影响定向测试，不以 mock 代替真实依赖验证；规则见[编码规范](../standards/01-项目编码规范.md)。

<a id="troubleshooting"></a>

## 8. 故障定位对照

| 现象 | 首先检查 | 不能采取的捷径 |
| --- | --- | --- |
| Gateway 502，但 IDE 本机可访问 | Nacos advertised 地址、容器到宿主端口、防火墙、旧实例 | 把注册地址固定为 127.0.0.1 |
| 登录后回调失败 | PUBLIC_ORIGIN、精确回调、可信代理头、state、Cookie | 开启任意回调通配 |
| BFF 换 token 失败 | IDENTITY_INTERNAL_ORIGIN 在容器内是否可达、issuer 校验 | 关闭 issuer 校验 |
| Nacos 修改未生效 | 字段归属、发布摘要、热更新白名单、是否需要重启 | 重复放入 env/Nacos 试覆盖 |
| 403 | 用户角色、客户端 scope/audience、租户能力 | 临时移除后端鉴权 |
| 可选消息未消费 | Outbox、broker、业务消费者、隔离队列 | 无限重投掩盖业务失败 |
| SSE 卡住 | 业务事件来源、代理缓冲、心跳与超时 | 无条件重发有副作用请求 |
| 修改后数据库报错 | 已执行迁移、schema 兼容、迁移账号/运行账号 | 修改历史迁移或开启自动建表 |
| 切换租户后数据混杂 | principal、事务租户上下文、连接 reset、缓存 key | 前端过滤掩盖后端泄漏 |

排查顺序沿 trace/request 从入口到实际写入；区分已证实事实、候选原因和缺失证据。共享日志前移除凭据及业务敏感内容。

<a id="reset"></a>

## 9. 停止、恢复和明确重置

日常结束使用 Compose stop 或停止 IDE，保留卷和本地秘密；恢复时沿初始化检查点核对，不需要重建租户。切回容器先关闭 IDE 进程、确认实例摘除，再对指定服务 up -d。

只有明确要删除本地数据才执行重置维护流程：核对 PROJECT_CODE/APP_ENV=local、实际网络/卷/目录清单、备份需要，明确列出将删除的数据并确认；使用具体资源名操作。测试/生产环境不开放 local reset。禁止把 `down -v` 写进普通启动、调试或升级命令。

新增业务数据库使用 resources 的增量初始化；丢失本地秘密不能自动生成新密码后假装旧数据库可用，应核对现有资源并执行明确的凭据轮换或受控重置。
