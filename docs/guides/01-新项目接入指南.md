# 新项目接入指南

> D-20261027-10 实施目标；本次改造尚在实施，命令可用性和运行证据见[计划](../plans/2026-10-27-源码微服务脚手架改造-plan.md)。Docker 验收暂停，不能据本指南推断已跑通。

## 1. 工具与工作目录

准备 Git、Python 3.12、uv、JDK 21 和 Docker Engine/Compose。创建不需要启动 Docker；初始化需要。VS Code 安装 Java Extension Pack、Python、Python Debugger。发布控制机用 Linux/WSL 的 Ansible，业务开发不需要 Ansible。

## 2. 创建项目

在已检出的脚手架根准备工具环境，ref 必须是包含目标创建器的固定提交，不能用未提交工作区冒充已发布版本：

```bash
uv sync --frozen
uv run --frozen python scripts/create.py --ref <固定提交> --output ../equipment-platform --project equipment-platform --java-service equipment-service --java-package com.acme.equipment --python-service inspection-service --python-package inspection --port-offset 0
cd ../equipment-platform
uv sync --frozen
./mvnw.cmd -pl :equipment-service -am spotless:apply
uv lock --project services/inspection-service
uv sync --frozen --project services/inspection-service
```

预期：sdk/java、sdk/python、两基础服务和两业务服务在本项目；没有框架 vendor。初始业务属于主仓；后续服务才用 submodule。创建器不提交/push，团队审核后自行提交源码、锁与共享 .vscode。目录职责见[设计](../design/11-源码脚手架交付与开发体验设计.md#layout)。

## 3. 初始化与登录

在生成项目根执行：

```bash
uv run --frozen python scripts/init.py --env local --services all
```

需要演示账号时显式追加 --with-demo；Linux 加 --dev-host <宿主私网地址>。Docker Desktop 可使用双方可解析的 host.docker.internal。不要将容器里的 localhost 当作宿主；端口冲突在初始化前调整配置，不杀其他项目进程。

init 会准备开发/迁移镜像，创建组件和资源，先发布 Nacos 配置再启动身份，分阶段登记技术身份、发布权限目录并执行业务迁移。输出实际入口、服务文档 URL、首次密码文件路径，不输出密码。只报告基础环境就绪，业务还需要启动。

无演示数据时：打开输出的 /identity/admin/ → 平台管理员完成首次改密 → 创建租户/租户管理员 → 客户端管理为业务 BFF 与本地 Swagger 允许该租户 → 租户管理员进入本租户创建普通用户/角色、分配业务权限 → 普通用户登录业务页。平台账号不是业务租户账号；客户端允许租户为空不代表全部。

演示模式使用输出的 alpha/beta、admin/writer/denied 和各自密码文件。首次改密后 writer 可访问示例，denied 应拒绝；两个租户看不到对方记录。重跑不重置密码。正常初始化和演示初始化均遵循[首次登录合同](../design/11-源码脚手架交付与开发体验设计.md#initialization)。

## 4. 启动与接口调试

VS Code 从项目根打开，分别 F5 Java/Python 或 compound；或两个终端：

```bash
uv run --frozen python scripts/dev.py equipment-service
uv run --frozen python scripts/dev.py inspection-service
```

访问业务页登录普通用户，创建/查询记录并访问对端。Swagger 使用 dev.py --tenant-code <租户编码>（F5 会提示），打开 init 输出的 URL，Authorize 选择 scope→身份页选择组织并登录→同意→Try it out。使用原生 PKCE，不填写 client_secret，不从 BFF 导出 token。过期重新授权；无权限应 403，不能临时删除后端校验。

F5 不隐式迁移/安装演示数据；停止只结束调试进程，基础设施用生成的 Compose task 查看日志或 stop，不 down -v。详见[开发调试](02-开发调试指南.md)。

## 5. 新增服务与另一位开发者

在兼容版本框架根生成独立服务仓库；下面为 Python 示例，Java 使用 language java 与点分包名：

```bash
uv run --frozen python scripts/create_service.py --language python --name scoring-service --package scoring --project-root ../equipment-platform --output ../scoring-service
```

进入独立目录自行 git init、提交、建立远程并 push；返回主项目：

```bash
uv run --frozen python scripts/add_service.py --repo <远程URL> --ref <完整提交> --language python --name scoring-service --package scoring --port 48085
uv run --frozen python scripts/init.py --env local --services scoring-service
```

新服务在宿主 services/scoring-service 开发；独立仓库不携带 SDK，不保证单独任意目录构建。接入不重写子仓锁。初始化保留已有 BFF 策略；管理员核对并更新 audience/scope，允许所需租户并分配角色权限后更新 BFF 请求范围、退出旧会话重新登录。旧 token 不会获得新增权限。

开发者先 push 服务提交，再提交主项目 gitlink/登记/配置。B 使用 git clone --recurse-submodules，已有克隆补 git submodule update --init --recursive；不 update --remote。B 的独立 local 从零初始化，不需要复制 A 的 .local；连接共享环境则通过受控渠道取回原秘密，不能生成替代密码。B 可按同一流程新增第四服务。

## 7. 常见停止原因

- 配置未发布：先看 init 停在哪个阶段，不绕过 Nacos 首次校验。
- 401/403：分别核对 token、角色、客户端、scope/audience 和租户允许范围；新增后重新登录。
- 本机 API 通、网关不通：检查 DEV_HOST、服务监听、防火墙和 Nacos 注册地址。
- 新服务文件冲突：查看候选差异，保留原文件；不要删除整个目录或修改子仓 HEAD 掩盖问题。
- 迁移 unknown：核对数据库活动、历史和执行进程后恢复，不再次盲跑。
