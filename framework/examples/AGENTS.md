# 项目协作规则

默认使用中文。先读 README.md、docs/standards/01-项目编码规范.md 和对应语言规范；操作见 docs/guides/04-新项目开发与规范升级指南.md。

- services/ 同时容纳 Java/Python 业务；config、infra、deploy 各司其职；不要复制框架基础服务源码。
- 修改前说明目标、影响和验证方法，普通改动在当前方案得到明确确认后实施。跨模块/接口/数据库/部署改动先写 docs/plans/YYYY-MM-DD-主题-plan.md，确认后实施；明确的既有授权不重复询问。
- 只做当前请求，不全仓重构/格式化。先实现，再集中补充和运行相关测试；未经明确要求不跑全仓或重启其他项目容器。
- Java 使用根 Maven wrapper 与服务 POM；Python 在服务自身环境检查，根 uv 环境只用于运维工具。检查命令见语言规范。
- 身份/租户/事务/错误/远程调用复用 SDK，不通过请求自报字段建立信任。
- 保留无关未提交工作；不提交 .local、秘密、Cookie、产物和缓存。提交与推送按用户授权执行。
- 汇报实际命令、结果和未验证部分，不将跳过或静态检查说成运行验收通过。

项目额外规则按需写入 docs/standards/04-项目补充规范.md；不存在该文件时无需创建。上述规则不依赖个人技能、CodeGraph 或 MCP 安装。
